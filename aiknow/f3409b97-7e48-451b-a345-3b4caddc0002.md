# Вложенная память цепляется на ПРОЧИТАННЫЙ ФАЙЛ, а не на cwd: работа в репозитории с `.claude/` даёт ДУБЛЬ корпуса

## Принцип

Claude Code прикрепляет вложенную память (`attachment: nested_memory`) **по триггеру на чтение файла**, а не по рабочему каталогу: `FileReadTool` кладёт путь в `nestedMemoryAttachmentTriggers`, затем обход поднимается по **предкам этого пути** и цепляет найденные `.claude/`.

⛔ Отсюда контринтуитивное следствие: **сменить cwd — не помогает**. Сессия может стартовать из каталога, у которого в предках нет ни одного `.claude/`, и всё равно получать корпус целиком — достаточно прочитать один файл внутри дерева, где он есть.

Уровни при этом **разные**: глобальный корпус (`~/.claude/`) приходит **системным промптом** и даёт ~одно событие вложения; project-уровень приходит **вложениями** и переприкрепляется **заново после каждой компакции**. Поэтому в репозитории, который сам хранит корпус правил (здесь — `dotfiles`), сессия несёт его **дважды**, и вторая копия растёт линейно по числу компакций.

## Когда правило срабатывает

- Сессия/воркер работает в worktree репозитория, у которого есть `.claude/` с правилами (`dotfiles` — главный случай).
- Симптом: компакция каждые несколько ходов при, казалось бы, небольшой работе.
- Соблазн объяснить раздутие «большими tool-результатами» или «длинными ответами».

## Диагностика — мерить СОСТАВ транскрипта, а не его размер

Общий размер ничего не говорит о причине. Считать надо по **типам записей** (вложения — отдельные строки jsonl, не часть `message`):

```python
a = e.get("attachment")            # запись верхнего уровня, type == "attachment"
a["type"]                          # nested_memory | file | skill_listing | …
a["content"]["type"]               # User | Project  ← ключевой разрез
a["path"]                          # что именно прицепилось
```

- ⛤ **Разрез `User` vs `Project` и есть диагноз.** Подавляющий `Project` при одном-двух `User` = дубль из рабочего дерева, а не «правил много».
- ⛤ **Сырое число событий обманчиво — раскладывай на уникальные пути × повторы.** 645 событий оказались 98 файлами, прицепленными по 7 раз (по разу на компакцию). Первое читается как «механизм сошёл с ума», второе — как «дедуп работает, но сбрасывается компакцией».
- ⚠ **Байты против символов.** `os.path.getsize` и `sum(len(line))` расходятся в разы на кириллице (`\uXXXX`-экранирование в jsonl). Сравнивать долю одной меркой, иначе получишь мнимое расхождение и уйдёшь искать несуществующий дефект.

## Рычаг

**`--setting-sources user`** (значения `user, project, local`; подтверждено `claude --help`). снимает **project-дубль CLAUDE.md-памяти — и только его**: загрузчики CLAUDE.md разнесены по уровням (`IY("projectSettings")` / `IY("userSettings")`). ⛔ **Каталог `~/.claude/rules` НЕ гейтится НИ ОДНИМ** setting-source и флагом не отключается вовсе — а это **59 % префикса** (замер ниже). Механизм и единственный per-file рычаг — §Addendum 2026-08-07 и §Addendum 2026-08-12 ниже.

⛤ **Но «не отключается» верно только про ФЛАГИ: корпус ключуется на `CLAUDE_CONFIG_DIR`.** Замер 2026-09-06: бот-сессия при том же `HOME`, но своим конфиг-каталогом (`~/.kitelev-claude`, где каталога `rules` нет) стартует с **47 007** ток против **604 997** у обычной. ⇒ у переменной есть эффект, которого нет ни у одного флага. ⛔ Рабочей сессии это НЕ рычаг (уносит скиллы, агентов, хуки и упирается в OAuth) — годится как объяснение, почему боты дёшевы, и как контроль «меряется именно корпус».

⛔ **`CLAUDE_CODE_DISABLE_CLAUDE_MDS` для этой цели НЕ годится**: он режет корпус **целиком**, включая глобальный (`DISABLE_CLAUDE_MDS ? [] : await yX()`), то есть отнимает у сессии её рабочие правила.

⚠ Флаг управляет **настройками целиком**, а не только памятью: вместе с project-памятью уходит project-`settings.json`. Прежде чем ставить — посмотреть, что там лежит. В `dotfiles`-worktree это тот же файл, что глобальный (симлинк), то есть теряется дубль; в прикладном репозитории может лежать что-то содержательное.

## ⛔ Addendum 2026-08-07 — уточнение §Рычаг: `--setting-sources` НЕ отключает КАТАЛОГ ПРАВИЛ; единственный per-file рычаг — frontmatter ⛔ (ключ **`paths:`**, НЕ `globs:` — см. §Addendum 2026-08-12)

§Рычаг выше говорит «уровни отключаются раздельно» — это верно **для CLAUDE.md-памяти** и **неверно для `rules/`**. Обратная разработка бандла (`@anthropic-ai/claude-code/cli.js`):


- ⛔ **`hJ1()` не гейтится ни одним setting-source** ⇒ основной корпус `~/.claude/rules` **невозможно** отключить флагом. Ключа `rules` в схеме `settings.json` нет вообще — загрузка каталогов это жёсткая конвенция кода, не конфиг.
- ✅ **`rules-archive/` вне флора ПО ПОСТРОЕНИЮ, а не по удаче:** строка `'rules-archive'` встречается в бандле **0 раз**; обход идёт ровно по двум жёстко заданным именам плюс `<предок>/.claude/rules` и не рекурсивен по соседям.
- ⛤ **Единственный per-file рычаг — `globs` во frontmatter самого правила.** Загрузчик каталога фильтрует `Z.filter(f => z ? f.globs : !f.globs)` при `conditionalRule:!1` ⇒ **во флор попадают только файлы БЕЗ `globs`**; файлы **с** `globs` прикрепляются **условно**, матч идёт по **пути файла, которого касается сессия**, семантикой пакета `ignore` (как `.gitignore`).
- ⚠ **Проба ОБЯЗАТЕЛЬНА до внедрения и обязана быть ФЛИПОМ:** правило с `globs` → сессия трогает подходящий путь → правило видно; не трогает → не видно. Без обеих половин проба тождественно зелёная. ⛔ Решающий риск: vault-операции идут **через Bash** (`exocortex-cli`), а не через file-tools — если триггер только file-tools, правило не прикрепится там, где оно нужнее всего, и floor исчезнет **молча**. Поэтому кандидаты — только правила с узким, механически определимым доменом.

⛤ **Цена, ради которой это стоит мерить** (замер по 261 usage-записи одной 56-минутной сессии): медианный префикс хода **943 063 ток** (94 % окна), always-on флор = **59 %** этого префикса, суммарный вход 246,6 М ток, стоимость **$192**. Диета, применённая ДО сессии, сэкономила бы **21,0 М входных токенов ≈ $10.5 в ней одной**.

## ⛤ Addendum 2026-08-12 — УСЛОВНАЯ ЗАГРУЗКА РАБОТАЕТ, и ключ frontmatter — **`paths:`**, а НЕ `globs:` (обе половины флипа предъявлены замером)

§Addendum 2026-08-07 выше называет `globs` единственным per-file рычагом и требует флип-пробы.
⛔ **Имя ключа там НЕВЕРНО** — и это ровно тот класс, против которого стоит само правило: подпись,
не выведенная из механизма. Прочитано в бандле (`/usr/local/lib/node_modules/@anthropic-ai/claude-code/cli.js`):

```js
function Xp9(A){ let{frontmatter:q,content:K}=cj(A);
  if(!q.paths) return {content:K};                                  // ← ключ frontmatter = paths
  let Y=l21(q.paths).map(z=>z.endsWith("/**")?z.slice(0,-3):z).filter(z=>z.length>0);
  if(Y.length===0||Y.every(z=>z==="**")) return {content:K};        // `**` целиком ⇒ НЕ условное
  return {content:K,paths:Y} }                                       // внутреннее имя поля — globs
```

⇒ frontmatter `globs:` игнорируется молча, правило остаётся во флоре. **Внутреннее** имя поля (`f.globs`
в фильтре `Z.filter(f=>z?f.globs:!f.globs)`) и **внешнее** имя ключа — РАЗНЫЕ; читать надо парс, а не фильтр.

**Механизм доставки:**
- Условный загрузчик `SJ1` вызывается для **всех трёх уровней** — `SJ1(A,Y,"Managed",…)` · `SJ1(A,z,"User",…)` · `SJ1(q,z,"Project",…)`. `Managed` = `~/.claude/rules` ⇒ основной корпус условно-загружаем.
- База матчинга для Managed/User — **`HA()` (cwd)**: абсолютный путь приводится к относительному от cwd (`Op9($,A)`), матчится семантикой пакета `ignore`. ⇒ писать `**/`-префикс (`**/packages/**`), иначе из другого cwd не совпадёт.
- Трейлинг `/**` парсер срезает; шаблон `**` целиком делает правило **не**-условным.

**Замер (A/B/A, 258 КБ под `paths:`):** `469 755 → 398 045 / 396 956 → 469 755` ⇒ **−72 254** при предсказании формулы −73 000. Позитивная половина: headless-сессия в `~/Developer` читает `…/packages/cli/jest.config.js` → префикс `490 947 → 490 947 → **593 230**` (**+102K**: 72K правил + project-`CLAUDE.md`). Обе половины предъявлены **ростом префикса**, а не самоотчётом.

⛔ **Триггер — ФАЙЛОВЫЙ, поэтому Bash-нужные правила условными делать НЕЛЬЗЯ.** Правило про наблюдение CI (`gh api`), релиз, `git commit`, vault-мутацию (`exocortex-cli`) нужно ровно тогда, когда файл-тулы **не** вызываются ⇒ оно не придёт. Дискриминатор при отборе: «возникает ли нужда в этом правиле РОВНО в момент чтения/правки матчащего файла?» Нет ⇒ оставить во флоре.

⛔ **ИНСТРУМЕНТ ЗАМЕРА, ПРЕДПИСАННЫЙ ЗДЕСЬ, МЁРТВ (проверено 2026-09-06).** Прежняя редакция: «`claude -p 'x' --model claude-haiku-4-5-20251001` падает `Prompt is too long` и печатает точный префикс `the request is ~NNNNNN tokens`». CLI отвечает **голым** `Prompt is too long` — числа нет ни в `--output-format json`, ни в `--debug`. ⚠ Отказ тихий: команда «работает», просто не отвечает на вопрос ⇒ читается как «замерить нельзя».
✅ **Рабочий замер — БЕСПЛАТНЫЙ и ничего не запускает:** первая запись `usage` в транскрипте (`~/.claude/projects/<slug-cwd>/<session_id>.jsonl`), сумма `input + cache_creation + cache_read`. `session_id` = имя каталога scratchpad сессии.
✅ **Предсказать БЕЗ сессии** — калиброванная модель в `child-spawn-context-floor` (регрессия по 54 историческим сессиям, R²=0.99).
⛔ **Контроль `mv ~/.claude/rules ~/.claude/rules.OFF` НЕ ИСПОЛЬЗОВАТЬ** — это мутация ОБЩЕГО состояния: в окно замера стартуют боты и параллельные сессии, и они поднимутся без корпуса. Изоляция берётся `CLAUDE_CONFIG_DIR` (строка выше), ⚠ но проба под ним упирается в OAuth (креды живут вне конфиг-каталога).

✅ **Доставка проверена ЖИВЫМ замером в обе стороны** (cwd = worktree, две headless-сессии):
контроль читает `AGENTS.md` (не матчит) → скачок **+32 507** (только project-память); проба читает
`packages/core/src/index.ts` (матчит `**/*.ts`) → **+59 324**. Разница **+26 817** = доставленные
правила. ⛤ Предсказание по байтам давало 36K — расхождение **языковое**: коэффициент 0.2766 ток/байт
снят на кириллическом корпусе, а эти девять англо/кодовые (~0.21 ток/байт). ⇒ ⛔ переносить один
коэффициент на правила разного языка нельзя; для оценки экономии брать замер, а не формулу.

⛔ **ДВА способа сделать глоб мёртвым (оракул `git check-ignore`, та же семантика):** абсолютный путь
(движок релятивизирует тестируемый путь ⇒ не совпадёт никогда) и файл **вне cwd** (даёт `../…`,
сегмент `..` не матчит ничего). ⇒ условное правило доставимо **только для файлов ПОД рабочим
каталогом**; правило с vault-доменом условным делать нельзя. Найдено на живом примере: `vault-operations`
несло абсолютные глобы и было молча отсутствующим — возвращено во флор.
