**Rule:** В скилле `/exocortex-asset` GATE 0.0 («CLI-create canonical, Write = fallback») стоит НАВЕРХУ файла, а раздел `## Asset Templates` (Write-шаблоны с YAML frontmatter) — далеко внизу. При выполнении задачи «создай ассет» **прочитать и явно применить decision order GATE 0.0 ПЕРЕД** тем как проскакивать к разделу Templates — не просто «скилл открыт, значит правила в контексте».

**Why:** Проскакивание к Templates — это не незнание правила (оно было в system-reminder всей сессии), а **привычка** идти к готовому YAML-шаблону вместо проверки «а можно ли через CLI». Cost пропуска низкий, если позже honesty-check ловит его (как здесь), но при накоплении — систематический обход GATE 0.0 для всех новых ассетов означает: (a) ручная генерация UUID/timestamp вместо авто, (b) обход built-in co-location логики CLI (verified v16.163.0+ она уже сама co-located), (c) потеря floor-практики «попробовал CLI → не смог → issue + fallback», которая создаёт трассируемость CLI-гэпов.

**Detection:** Пользователь спросил «Почему ты создал X не через exocortex-cli?!» — сразу после того как ассет уже был написан через Write и запушен на remote. Честная перепроверка через `--dry-run` показала: CLI **полностью** мог это сделать (та же co-located папка `assetspaces/kitelev/exoas-exoass/exoass/`, корректный frontmatter).

**Recovery pattern (когда пропуск уже обнаружен):**
1. НЕ оправдываться «CLI бы не справился» без проверки — сделать `--dry-run` и честно сравнить.
2. Если контент уже на remote и SHACL clean — не нужно молча оставлять incorrect-process residue: спросить пользователя explicit choice (оставить / пересоздать), не решать самостоятельно.
3. Если пересоздают: `rm` старый файл → `exocortex-cli create --property ... --body-file <saved-content>` → SHACL post-validate (cache-clear) → ExoSync push → verify remote (`gh api .../commits/<sha>` + `contents/<old-path>` 404 + `contents/<new-path>` 200). Новый UUID — старый становится orphan; это ок для aiKnow/inbox-класса без inbound wikilinks.

**Pattern (для будущих Skill-driven ассет-задач):** Открыл скилл `/exocortex-asset` → ПЕРВЫЙ содержательный шаг = перечитать GATE 0.0 decision order (CLI-support-check → CLI-create, ИЛИ issue+fallback), а не искать подходящий Write-шаблон.

Cost: 1 delete + 1 recreate + 1 ExoSync round-trip; урон 0 (self-caught до потери контента, verified остаточно на remote).
