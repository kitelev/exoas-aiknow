# Prefer codegraph for structural code audits

При **structural** вопросах про код — «как работает X», «trace path of Y», «кто вызывает Z», «что сломается если изменить W» — **первый инструмент = codegraph MCP**, не `Read` / `bash grep` / `Glob`.

## Когда правило срабатывает

| Сигнал | Trigger? |
|---|---|
| User говорит «как работает X», «как устроено X», «trace X», «who calls Y», «what calls Y», «callers of Z» | ✅ |
| Open task: cross-file architecture audit / refactor planning / impact assessment перед изменением symbol | ✅ |
| Plan: ≥3 Reads on same `src/` directory **OR** ≥1 bash grep по symbol name **OR** ≥2 Glob calls по symbol pattern | ✅ — пересмотреть до выполнения, попробовать codegraph_search first |
| Quick bug-fix: уже знаешь file:line + правка одной строки | ❌ — Read достаточно |
| Literal text search: comment content / log message / docstring string / URL | ❌ — grep быстрее, codegraph не индексирует comments как searchable text |
| Vault assets (markdown, RDF frontmatter, knowledge base) | ❌ — codegraph не парсит markdown; используй exocortex-cli SPARQL |
| `.codegraph/` отсутствует в repo root | ❌ — index не инициализирован; либо init (`codegraph init -i`), либо fall back на Read/grep |

## Mechanical pre-check

Перед открытием серии `Read` / `bash grep` на code repo:

```bash
# 1. Detect if repo has codegraph index
REPO=$(git rev-parse --show-toplevel 2>/dev/null)
[ -d "$REPO/.codegraph" ] && echo "INDEX_AVAILABLE=true" || echo "INDEX_AVAILABLE=false"

# 2. If true → call codegraph_search / codegraph_context / codegraph_callers FIRST
#    Если возвращает достаточный ответ — stop. Read только для smoking-gun nuance layer.

# 3. If false → fall back на Read/grep, опционально предложить user init
```

## Decision tree

```
Question typed: «How does X handle Y» / «trace X» / «callers of X»
                                │
                                ▼
                ┌────────────────────────────┐
                │ codegraph index в repo?   │
                └──────────────┬─────────────┘
                          yes  │  no
                ┌──────────────┴─────────────┐
                ▼                            ▼
   codegraph_search X         git status to find repo root,
   (locate symbol)            then Read/grep fallback.
        │                     Optionally ask user
        ▼                     to init codegraph.
   codegraph_context "<task>"
   (entry + breadcrumbs)
        │
        ▼  partial картина?
   codegraph_explore <symbol-A>, <symbol-B>, ...
   (cooperating files)
        │
        ▼  smoking-gun detail?
   Read <file>:<line>  ← only this targeted, not whole file
```

## Escape clauses

- **`codegraph_context` is PARTIAL by design.** Verified empirically — для multi-file architectural narrative оно даёт entry point + breadcrumbs (~30-40% картины), а **не** weather report о всех cooperating files. После `codegraph_context` обычно нужен `codegraph_explore` на 3-5 symbols которые context промахнулся surface'нуть. Не считать `codegraph_context` standalone-ответом.
- **Tree-sitter не парсит markdown / yaml / shell в полную AST.** Для shell `.sh` files в `~/.claude/hooks/` / `~/.claude/lib/` codegraph index OK (есть basic function support через bash tree-sitter parser), но для markdown (vault, docs) — не работает.
- **Comment-only context (issue numbers, RFC references inside `//`) codegraph не surface'ит как searchable.** Если ищешь string `"Issue #3171"` или `"RFC c78cc5c8"` — `bash grep -rn` или Grep tool корректнее.
- **Index lag**: file watcher debounces ~500ms behind writes. Не запрашивай codegraph immediately после editing файла в той же turn — данные stale; либо запроси через несколько секунд, либо Read измененный файл.

⚠ Побочный tell из occurrence 21 (bash, не codegraph): `awk '…{print NR…}'` по file-glob даёт **накопительные** номера строк, а не per-file — нужен `FNR`. (Там же: `bash grep` молча вернул пусто на 1116-строчном файле, из-за чего `awk` и стал фолбэком.)
