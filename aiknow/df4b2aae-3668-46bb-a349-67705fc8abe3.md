# Worktree cleanup: merge-detection через gh PR state, submodule-обход, защита активных

## Принцип

Накопившиеся git-worktree-ы (в `exocortex-development/worktrees/` их бывает 50+) чистить **только по authoritative-признаку «PR смержен»**, а не по git-родству. Удалять — лишь `MERGED` + чистое дерево (по `status --porcelain --ignored`, иначе gitignored-файлы невидимы) + не в активной сессии.

## ⛔ git ancestry / net-diff НЕ детектируют squash-merge

Репозиторий мержит **squash** → у смерженной ветки её коммиты НЕ становятся предками origin/main. Поэтому:
- `git merge-base --is-ancestor <head> origin/main` → **false** для смерженных squash-веток (выглядят «N ahead»).
- `git diff origin/main <head>` (net-diff) → **непустой** даже для смерженных, потому что main ушёл вперёд (десятки PR-ов merged за день) → ветка «отстаёт» = diff присутствует.

Оба метода дают ложную картину. **Authoritative = статус PR через gh:**

```bash
# zsh не word-split'ит — итерируй через while-read, НЕ for x in $LIST (см. bash-loop-eval-pitfalls)
while IFS= read -r br; do
  st=$(gh pr list --repo <owner/repo> --state all --head "$br" \
        --json state,number --jq '.[0] | "\(.state) #\(.number)"' 2>/dev/null)
  echo "${st:-NO_PR}|$br"
done <<'BRANCHES'
<branch-1>
<branch-2>
BRANCHES
```

Классификация по результату:

| PR state | Контент в main? | Действие |
|---|---|---|
| `MERGED #N` | да | ✅ удалить worktree + ветку (`git branch -D` после `worktree remove`) |
| `CLOSED #N` | нет (PR отклонён) | ⚠️ surface — работа не в main; решает user |
| `NO_PR` (null) | нет (PR не открывали) | ⚠️ surface — коммиты только в ветке |

## ⛔ Никогда не авто-удалять

- **Грязные worktree-ы** (`git -C <wt> status --porcelain --ignored` непусто — ⛔ без `--ignored` локальный `.env`/дамп не виден) — чужая незакоммиченная работа параллельных сессий. Surface, не трогать.
- **Worktree-ы активных сессий** — перед чисткой: `tmux list-sessions` + `tmux display-message -p '#{pane_current_path}'` по каждой claude/orch/child-сессии; исключить их worktree-пути и связанные программы (например DAG-программа держит несколько `task-*`/`feat-*` worktree-ов).
- Дерево main checkout (сам репозиторий) — никогда.

## ⛤ `git worktree remove` не берёт worktree с submodule-ами

Если worktree содержит инициализированные submodule-ы:
```
fatal: working trees containing submodules cannot be moved or removed
```
`--force` не помогает. Обход (worktree verified clean+merged → safe):
```bash
rm -rf "<worktree-path>"           # дерево чистое ПО `--porcelain --ignored` + контент в main → безопасно
git worktree prune -v              # снять admin-ссылки (gitdir points to non-existent)
git branch -D <merged-branch>      # после prune
```
Для не-submodule worktree-ов `git worktree remove <path>` (без --force; откажется если грязно — safety-net **только для ОТСЛЕЖИВАЕМОГО**: файл под `.gitignore` он не видит и сносит МОЛЧА, rc=0 — проверено живым git, §Addendum 2026-08-07).

## ⛔ Addendum 2026-08-07 — оба слоя защиты работы ключуются на том, что ВИДИТ git ⇒ файл под `.gitignore` не покрыт НИ ОДНИМ и сносится молча

Строка выше называет `remove` без `--force` «полезным safety-net». Недостающая половина — **граница** этого net'а. У worktree два слоя, оберегающих чужую работу, и оба смотрят на git-индекс:

| слой | что бережёт | чем ключуется |
|---|---|---|
| ветка (`worktree add -b`) | **закоммиченное** | ref живёт после сноса дерева |
| `remove` **без** `--force` | **незакоммиченное отслеживаемое** | `status --porcelain` непуст |

⛤ **Файл под `.gitignore` не виден НИ ОДНОМУ:** в индекс не попал ⇒ веткой не сохранён; в `status --porcelain` не появляется ⇒ `remove` считает дерево чистым и **сносит без единого предупреждения**. То есть «уборка безопасна» верно для двух из трёх классов содержимого, а третий теряется тише всего.

- ⚠ **Симптом-tell отсутствует по построению.** Потеря отслеживаемого даёт отказ уборки (видно в логе); потеря игнорируемого не даёт **ничего** — дерево просто исчезло вместе с локальным `.env`, скачанным дампом, свежесобранным артефактом.
- ⛔ **Дискриминатора «ценная работа vs сборочный мусор» дёшево НЕТ.** В свежем чекауте exocortex уже ~20 игнорируемых записей, все сборочные — эвристика «есть игнорируемое ⇒ не сноси» превратила бы уборку в no-op на каждом дереве.
- ✅ **Floor: назвать границу, а не обещать безопасность.** Автоматическая уборка вправе сносить игнорируемое (иначе она не работает), но её потребитель обязан знать: `git add -f <файл>` — единственный способ провести локальный артефакт через слой ветки. Это ровно `decision-surface-must-derive-from-mechanism`: подпись «уборка не тронет твою работу» не выведена из механизма, а честная — «не тронет то, что видит git».
- ⛤ **Симметрично для РУЧНОЙ чистки** (`rm -rf` из §submodule выше): `status --porcelain` чист ≠ «в дереве ничего твоего». Перед `rm -rf` смотреть `git -C <wt> status --porcelain --ignored | head`, если дерево вообще могло использоваться под сборку.
## ⛤ У `--ignored` ДВЕ РАЗНЫЕ цели, и для КЛАССИФИКАЦИИ он непригоден

Правило требует `status --porcelain --ignored` — верно, но цель у флага **одна из двух**, и
смешивать их нельзя:

| вопрос | форма | почему |
|---|---|---|
| «можно ли этот worktree удалять?» (**классификация**) | `--porcelain` **БЕЗ** `--ignored` | иначе ответ «ГРЯЗНЫЙ» у **каждого**: в любом собранном дереве лежат `node_modules`, `dist`, `.jest-cache`, `coverage` |
| «нет ли в нём ценного, что снесёт `rm -rf`?» (**проверка перед сносом**) | `--porcelain --ignored`, отфильтровав сборочное | ловит `.env`, дампы, скачанные фикстуры — их не покрывает ни ветка, ни safety-net |

⛔ Замер 2026-08-20 (14 worktree): `--ignored` пометил **ГРЯЗНЫМИ 14 из 14** ⇒ признак
тождественно-положителен и решения не даёт. `--porcelain` без флага дал **0 отслеживаемой грязи
у всех**, а состояние PR разделило их на 8 `MERGED` и 4 `нет PR` — это и есть работающий
дискриминатор. Проверка ignored-состава у кандидатов нашла только `build-meta.json` и
`.jest-cache/`, то есть сносить было безопасно.

✅ **Порядок:** `--porcelain` (классификация) → состояние PR → `--ignored` с фильтром
(`grep -vE 'node_modules|/dist|coverage|test-results|\.turbo|playwright-report'`) → снос.

⛤ **Пустой worktree — тоже кандидат, и его признак ДРУГОЙ:** `rev-list --count origin/main..HEAD`
= 0 при нулевой грязи ⇒ он не держит ничего, PR ему не нужен. Замер: 4 таких (в т.ч. detached-зонд
и рабочие копии на `main`/`main-check`). ⛔ Ветку `main` при этом НЕ удалять — сносится только
worktree.

**Итог того прохода:** 15 → 2 worktree, ~13 снесено, ни одной незакоммиченной строки не потеряно
(проверено детектором сирот до и после).

```bash
git worktree list --porcelain   # path/HEAD/branch на каждый

# clean ones: gh pr list --head <branch> → MERGED only = safe
```
