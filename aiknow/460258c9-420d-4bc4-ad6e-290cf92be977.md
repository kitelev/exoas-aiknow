# Мажорный бамп несёт НЕСКОЛЬКО независимых семантических осей — release notes называют одну, остальные находит только замер ОБЕИХ версий на СВОИХ входах

## Принцип

Мажорная версия меняет **не одну вещь**. Release notes и миграционный гайд описывают ось, которую автор счёл главной; прочие изменения приходят вместе с ней и **в заголовке не названы**.

⛔ Отсюда типовой промах: ты закрываешь названную ось (аккуратно, с тестами, с revert-verify) — и считаешь миграцию понятой. Остальные оси при этом остаются, и находит их **не ты, а потребитель**: CI, ревьюер или пользователь.

⛤ Дефект тише обычного, потому что работа выглядит добросовестной: у названной оси есть замер, есть гвард, есть зелёный прогон. Ощущение полноты создаётся качеством закрытия **одной** оси.

## Дискриминатор (одна команда, не чтение)

> **Прогони обе версии на СВОИХ реальных входах и сравни выход.**

Release notes отвечают на вопрос «что автор изменил намеренно»; тебе нужен ответ на «что изменилось **для моих данных**». Это разные вопросы, и второй решается только исполнением:

```bash
# старая версия (из main-чекаута / другого worktree)
node -e "const y=require('js-yaml'); try{console.log(JSON.stringify(y.load(ВХОД)))}catch(e){console.log('THROW')}"
# новая — тот же вход, тот же вывод рядом
```

⚠ Вход брать **свой** (реальная форма из vault/фикстуры), а не пример из документации: доку писали под названную ось.

## Симптомы-tell

- ⚠ Ты можешь назвать **ровно одну** причину, по которой бамп нетривиален. У мажора их обычно больше — спроси, какую вторую ты бы обнаружил, если бы она была.
- ⚠ Гвард, который ты добавил, **параметризован** (схема, флаг, опция) — значит ты нашёл ось, у которой есть ручка. Оси **без ручки** (строгость парсера, порядок обхода, дефолт таймаута) так не находятся: у них нет параметра, который бросился бы в глаза.
- ⚠ Прогнал не все пакеты монорепо. Ось, живущая в непрогнанном пакете, невидима по построению.

## Floor

1. **Прогнать ВСЕ пакеты, а не изменённые.** Ось может проявиться там, где ты ничего не правил — потребитель общей функции.
2. **Ноль тестов на свойство ≠ свойство не используется.** Замерить: сколько прод-модулей ветвится на нём. Расхождение «0 тестов / N модулей» и есть непокрытая ось.
3. ⛤ **Ось, у которой нет опции, чинится в СВОЁМ коде** — и лучше в централизованной точке, если она есть: один гвард закрывает всех потребителей, а не тот файл, где ты заметил.
4. **Предикат гварда мерить ДО выбора.** Естественный предикат («ключ должен быть строкой») способен отвергнуть легитимные данные; счёт на живом корпусе стоит один проход и превращает догадку в факт.

## Empirical reference

- **Дата:** 2026-08-20/21, `kitelev/exocortex`, js-yaml 4 → 5 (PR #4173).
- **Названная ось (release notes):** дефолтная схема YAML 1.1 → CORE, то есть bare-дата `Date` → `string`. Закрыта параметром `YAML11_SCHEMA` в 6 прод-точках + ось revert-verify на оба call-site.
- **Неназванная ось, найденная CI:** **строгость парсера**. `  : : :` бросал в 4.1.1 и парсится в 5.3.0 в `{null:{null:{null:null}}}` — **под всеми схемами**, то есть параметром не лечится (`LoadOptions` не имеет переключателя строгости). Прод начал отдавать мусорный объект вместо `{}` у **11** потребителей общей функции.
- **Почему не нашёл сам:** прогнал 2 пакета из 4 (core+cli), а упало в obsidian-plugin. Плюс у первой оси была «ручка» (схема) — она нашлась чтением; у второй ручки нет.
- **Побочно:** ноль тестов с `instanceof Date` при **4** прод-модулях, ветвящихся на этом типе.
- **Замер предиката гварда:** 26 572 файла, 260 914 ключей верхнего уровня, **0** резолвящихся не в строку ⇒ предикат ничего живого не отвергает. Без замера он выглядел рискованным (`on`, `y`, `12` — не-строки в YAML 1.1).
- ⛤ **Ложное срабатывание поймала контрольная ось**, а не я: `tags: [x, y]` → `["x", true]`, потому что `y` в YAML 1.1 булево. Ось «обычный frontmatter по-прежнему парсится» и существует ровно для этого.
