# WAITING_DECISION: Bash tool timeout overrides script timeout

> **⛔ ROOT-CAUSE FIXED 2026-06-05 (separate from the Bash-timeout issue below):** `child-await-decision.sh` грепал reply по литералу `"decision_uid":"<uid>"` (без пробела), а `parent-reply.sh` писал через `json.dumps` с пробелом после двоеточия (`"decision_uid": "<uid>"`) → **grep никогда не матчил** → child всегда уходил в timeout/default несмотря на доставленный reply. Это и есть «possible bug in script's reply parsing» из Incident 2 ниже. Fix: child-await грепает по **голому UID** (format-agnostic), parent-reply пишет **compact** JSON. Round-trip verified. Если видишь старый симптом — убедись, что обе lib-версии свежие (`~/.claude/lib` → dotfiles).

При вызове `~/.claude/lib/child-await-decision.sh` из child Claude Bash tool — **обязательно** передавать `timeout: 600000` в Bash invocation. Script's внутренний default `-t 1800` (30 min) **бесполезен** — Bash tool обрезает на `BASH_DEFAULT_TIMEOUT_MS=300000` (5 min) → script killed на 300s → child получает false timeout exit 124 → applies default option (часто wrong choice).

## Когда правило срабатывает

- Child Claude orchestrated parent (autonomous AI) ждёт parent decision via blocking `child-await-decision.sh`
- Question complexity такая, что parent decision может занять >5 min (parent thinks, consults advisor, или is busy with other tools)
- Default fallback option может быть wrong choice если parent не отвечает

## Правильный паттерн

В child Claude:

```bash
# WRONG — Bash tool 300s default kills script before parent reply
ANSWER=$(~/.claude/lib/child-await-decision.sh "Question..." "opt-a|opt-b")

# RIGHT — explicit timeout: 600000 in Bash tool invocation
# Inside child's Bash tool call:
#   command: ~/.claude/lib/child-await-decision.sh -t 540 "Question..." "opt-a|opt-b"
#   timeout: 600000  ← MANDATORY
ANSWER=$(~/.claude/lib/child-await-decision.sh -t 540 "Question..." "opt-a|opt-b")
```

Note: `-t 540` (9 min) leaves 60s headroom для Bash tool 600s cap. Don't set `-t 600` — race condition с Bash tool kill.

## Workaround если await pattern всё равно ломается

Direct reply file write (no UUID coupling):

```bash
# Parent side:
REPLY_FILE=~/.claude/audit/parent-replies-<child-tmux-name>.jsonl
python3 -c "import json; print(json.dumps({
    'ts': '<timestamp>',
    'child': '<child-tmux-name>',
    'decision_uid': 'inline-await-no-uid',
    'answer': '<answer text>'
}))" > "$REPLY_FILE"
```

Child's inline polling loop checks `[ -f "$REPLY_FILE" ]` и exits 0 как только файл exists — UUID игнорируется. Подходит когда `parent-reply.sh` не сработал (нет decision UID в WAITING_DECISION ping).

## Pattern summary (decision tree для child Claude)

| Situation | Approach |
|---|---|
| Quick yes/no parent decision, <2 min expected | `child-await-decision.sh` default timeout, no Bash tool override needed |
| Architectural decision, parent may take 5-30 min | `child-await-decision.sh -t 540` + Bash tool `timeout: 600000` |
| Long-running coordination, >10 min wait | Inline polling shell loop (file-existence check, no UID matching) + parent writes directly to reply file |
