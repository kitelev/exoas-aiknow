# Каждый созданный GitHub issue → зеркало `ems__Task` в vault (work-item живёт в графе, не только на GitHub)

## Принцип (user directive 2026-07-30)

**Любой issue, который я создаю на GitHub, ОБЯЗАН быть немедленно зазеркален в vault** как `ems__Task` — в той же сессии, сразу после `gh issue create`, без «потом». Vault — source of truth для work-items; issue на GitHub — рабочая поверхность для кода/ревью/PR, но **не** учётная запись работы.

Issue без зеркала = **невидимый work-item**: не попадает в SPARQL-обзоры («что у меня в Backlog»), не связывается с проектами/областями/lessons, теряется при resume новой сессии, не виден в EA-флоу приоритизации. Это тот же класс, что «WBS body-only вместо nested-графа» (`pmbok-wbs-nested-assets`) — work-item существует, но не queryable.

## Механика (канон)

**Проектный контекст** (issue относится к оркестрируемому `ems__Project`) → nested `ems__Task` под проект через `ems__Effort_parent` — см. `pmbok-wbs-nested-assets` §«Новый work-item → немедленно в граф». Это уже было; данное правило добавляет второй случай.

**Ad-hoc** (issue вне проектного контекста: находка аудита, dogfood-gap, chore) → `ems__Task` в `vault-exodev` **под контейнер-направление** `bbac67ce-eb22-44db-a9b9-6dcb6d8f6eb2` («Технический бэклог: ad-hoc находки и dogfood-гэпы»):

```bash
npx -y @kitelev/exocortex-cli@latest create \
  --vault /Users/kitelev/vaults/vault-exodev \
  --class 1b20a8f0-d745-4e93-91db-4531b3df120e \
  --label 'GitHub #<N>: <краткая суть>' \
  --property "exo__Asset_isDefinedBy=`32d2374c-1bef-4b64-ad23-e26b53b52df8`" \
  --property "ems__Effort_parent=`bbac67ce-eb22-44db-a9b9-6dcb6d8f6eb2`" \
  --property "ems__Effort_status=`753a44d5-846c-4b82-9196-4fd9a4d48777`" \   # ⛔ Backlog — только для СВЕЖЕГО issue; зеркаля существующий, статус выводи из его state
  --body-file <тело>
```

- `1b20a8f0-d745-4e93-91db-4531b3df120e` = `ems__Task`; `32d2374c-1bef-4b64-ad23-e26b53b52df8` = `$exodev` anchor (→ co-location в `exoas-exodev/exodev/`); `753a44d5-846c-4b82-9196-4fd9a4d48777` = Backlog. ⛤ Резолвить каждый свежим `find`, не дописывать по памяти (`vault-asset-creation` §Update 2026-06-12).

- ⛔ **`standalone` (без `ems__Effort_parent`) НЕ ВАРИАНТ.** Сирота в очередь vteam попадает
  (допуск по `flow__WorkItem_stage`), но ранг **наследует у ближайшего предка** по
  `ems__Effort_parent+` ⇒ без предка `rankSrc=absent` и сортировка уводит её **в конец**.
  ⛤ Обоснование переписывалось при смене носителя (ALP → vteam), floor устоял — **§A1**.
  - **Мутация родителя у существующего ассета — `apply set-parent`, НЕ `set-property`:**
    `Effort_parent` guarded, `set-property` отказывает fail-loud. Форма — **голый UID**:
    `apply set-parent <path> --input '{"parent":"<uid>"}' --yes` (executor оборачивает в
    ``…`` сам; передашь ``uid`` — получишь ``[[uid`]]`, см. `vault-asset-creation`).

- ⛔ **Backlog — дефолт для СВЕЖЕГО issue. Зеркаля УЖЕ СУЩЕСТВУЮЩИЙ** (bulk-свип, добор
  пропущенных), **статус выводи из состояния issue, а не из дефолта** — иначе зеркало
  рождается устаревшим и очередь показывает работу, которой нет (**§A2**).
  - **Floor (одна команда):** `gh issue view <N> --json state,closedAt` перед `create`;
    `CLOSED` ⇒ создавать сразу закрытым (`create` со статусом Done ЛИБО `apply start-effort`
    → `mark-done` следом), а в теле указать дату закрытия issue.
  - **Tell при разборе бэклога:** у зеркала `exo__Asset_createdAt` **позже** `closedAt` его issue.

- ⛔ **ЗЕРКАЛО СИММЕТРИЧНО: закрывая issue, закрой зеркало.** Правило выше гейтит статус
  **при создании**; закрытие дороже — зеркало пишется раз, а закрывается позже и в другой
  сессии. ⛤ Механизм («issue закрывается ЧУЖИМИ РУКАМИ» через `Closes #N`) — **§A3**.
  - ✅ **Floor: закрытие зеркала — часть отгрузки, наравне с `chmod +x`**
    (`harness-invocation-surface` §A5). Смержил PR с `Closes #N` ⇒ немедленно
    `apply mark-done <mirror-path> --vault <V> --yes`. Путь зеркала — за один запрос:
    `SELECT ?s WHERE { ?s exo:Asset_label ?l . FILTER(CONTAINS(STR(?l),"GitHub #<N>")) }`
    (префикс `GitHub #<N>:` в label заведён ровно для этого).
  - ⛔ **«Тем же ходом» проваливается СИСТЕМАТИЧЕСКИ при отложенном merge** (auto-merge, CI,
    ретраи) — момент закрытия наступает, когда внимание уже в другом месте (**§A4**).
    ✅ **Практический floor, не требующий памяти: закрывать зеркало НЕ по merge, а по СВОЕМУ
    следующему касанию vault** — свип ниже находит все отставшие разом.
    ⚠ **Tell:** закрыл зеркало у последнего PR и не помнишь, закрывал ли у предыдущих —
    не вспоминай, прогони свип.
  - ⚠ **Свип по всем зеркалам** (зеркало в `Doing`/`Backlog`, а его issue `CLOSED`):
    ```bash
    npx -y @kitelev/exocortex-cli@latest query --vault <V> --no-cache --format json \
      "PREFIX exo: <https://exocortex.my/ontology/exo#>
       PREFIX ems: <https://exocortex.my/ontology/ems#>
       SELECT ?s ?l ?st WHERE { ?s exo:Asset_label ?l . FILTER(CONTAINS(STR(?l),\"GitHub #\"))
                                OPTIONAL { ?s ems:Effort_status ?st } }"
    # → вытащить N из label → gh issue view N --json state → CLOSED ∧ статус ≠ Done = stale
    ```
  - ⛔ **ДВА дефекта самого свипа, оба дают ЛОЖНЫЕ находки (замеры — §A5):**
    (а) **метка `GitHub #N` не кодирует РЕПОЗИТОРИЙ** ⇒ репо брать из URL в ТЕЛЕ зеркала,
    а кандидатов без `ems__Effort_status` отбрасывать;
    (б) **статус матчить ОБЕИМИ IRI-формами** (`7b9b3116` **И** `ems#EffortStatusDone`) —
    `apply mark-done` пишет ``<uid>``, в граф уходит symbolic, и UID-only фильтр показывает
    Done-зеркала как незакрытые (`sparql-iri-form-pre-verify`).

- **Личное / рабочее** (не Exocortex-разработка) → `vault-my` / `vault-tbank` с их анкерами, а не exodev.
- **Label обезьяно-понятный** + префикс `GitHub #<N>:` (двусторонняя навигация; grep по номеру находит зеркало).
- **Тело**: ссылка на issue (`https://github.com/<o>/<r>/issues/<N>`) + что сделать + DoD. Дублировать issue целиком не нужно — issue остаётся authoritative для технических деталей; зеркало несёт учёт + контекст находки.
- **Backlog-гейт формулировки** (`executive-assistant`): в Backlog только с обезьянопонятной формулировкой без прокрастинатогенов.

**Обязательный floor после create** (CLI идёт через Bash → PreToolUse хуки co-location/validate-wikilinks/SHACL **не срабатывают**):
1. SHACL post-validate: `rm -f <vault>/.exocortex/cache/triples.json` + `validate schema --shapes-mode` → **0 new violations** (`shacl-validate-clear-cache`).
2. `exosync push --vault <vault> --token-from-gh` → зеркало доезжает на все устройства (`exosync-quarantine-triage` — parity ДО push, если рядом чужие pending).

## Обратное направление (уже энфорсится хуком, не путать)

`gh-issue-code-deliverable-gate.sh` (PreToolUse) требует, чтобы issue в code-репо был **CODE-deliverable** (маркер `# code-issue: <обоснование>`). Т.е.:

| Работа | GitHub issue | Зеркало в vault |
|---|---|---|
| Изменение кода (фича/баг/движок/CI-инфра) | ✅ да (+ маркер `# code-issue:`) | ✅ да (это правило) |
| Vault-data миграция / personal / EA-задача | ⛔ нет (не code-issue) | ✅ только `ems__Task` |

Т.е. issue **без** зеркала — всегда дефект; зеркало **без** issue — норма (большинство задач).

## Запреты

- ⛔ Создать issue и уйти к следующей задаче, не зазеркалив (даже «мелкий chore» — именно они и теряются).
- ⛔ Оставить зеркало на «конец сессии» / в next-session-prompt — зеркалим в том же ходе, что `gh issue create`.
- ⛔ Писать зеркало raw `Write`-ом вместо `exocortex-cli create` (`vault-asset-creation` §HOMOICONIC-FIRST: dogfood-путь; хук `dogfood-cli-mutation` блокирует new-file Write CLI-creatable instance-ассета).
- ⛤ Bulk-заведение issues (N>3 за проход) — зеркала тоже bulk, одним `create`-циклом + ОДИН SHACL + ОДИН push; не N×SHACL.

## ⛔ ТРЕТИЙ разрыв зеркала: работа идёт КОММЕНТАРИЯМИ в issue, а зеркало остаётся заглушкой

Два разрыва выше — про **статус**. Третий про **содержание**: разбор, замер, опровергнутая
посылка, решение пишутся комментарием в issue (там их прочитает GitHub-читатель), а зеркало
остаётся тем, чем создано. ⇒ Для графа этой работы **не существует**: обзоры, очередь и любой,
кто пришёл в задачу из vault, видят её неразобранной — и разбирают заново. Разбор — **§A6**.

- ⚠ **Симптом-tell, ловится СЧЁТОМ:** у issue **N > 0** комментариев, а в теле зеркала — меньше
  ~14 непустых строк (объём «создано и не трогали»). Пара чисел, оба дешёвые.
- ⛔ **Тонкое тело САМО ПО СЕБЕ дефектом НЕ является** — у свежего зеркала так и должно быть.
  Дефект — именно **расхождение**: там есть, здесь нет.
- ✅ **Floor: закончив разбор комментарием в issue, перенеси его в тело зеркала ТЕМ ЖЕ ходом.**
  Комментарий адресован GitHub-читателю, тело — графу; это два разных потребителя, и второй
  молчит о своей нужде.
- ✅ **Свип постфактум** — один проход, дёшев и повторяем:
  ```bash
  # зеркала → номер+репо ИЗ URL В ТЕЛЕ (метка «GitHub #N» репозиторий не кодирует!)
  # для каждого: gh issue view <N> --repo <repo> --json state,comments
  # разрыв = state OPEN и comments > 0 и непустых строк тела <= 14
  ```
- ⛔ **`set-body` отвергнет wikilink на не-ассет**, а комментарии ими полны (``правило``,
  ``uid``). Конвертировать в backtick перед переносом, иначе тело **молча не ляжет**.
- ⛤ **Ноль по свипу «issue CLOSED, зеркало не закрыто» — засчитывать ТОЛЬКО с канарейкой:**
  инвертировать предикат и убедиться, что согласованные пары находятся.

## Enforcement

**Механический:** PostToolUse(Bash) хук `~/.claude/hooks/gh-issue-mirror-reminder.sh` — детектит успешный `gh issue create` и напоминает про зеркало (advisory, ничего не откатывает — issue уже создан). Escape: маркер `# vault-mirrored: <причина>` в команде (зеркало уже есть / сознательно не нужно). Fail-open на любой не-issue-create Bash.

⛤ **Verified эмпирически 2026-07-30 (не wallpaper):** хук использует **exit 2** — единственный канал PostToolUse, чей stderr **реально доходит до модели**; проверено no-op-командой (`echo '… gh issue create …'`) сразу после регистрации → advisory пришёл в контекст как `PostToolUse:Bash hook blocking error`. ⛔ `exit 0` + stderr в контекст НЕ попадает (тот же механизм, что PreToolUse warn-only — `prefer-codegraph-for-structural-audits` empirical 2026-06-06; sibling `offer-closure-on-done.sh` использует exit 0 → вероятно wallpaper, отдельная находка). Заодно подтверждён **hot-reload `settings.json`**: хук, зарегистрированный ПОСЛЕ старта сессии, сработал на её же следующем tool-вызове без рестарта.

⚠ Взаимодействие с PreToolUse `gh-issue-code-deliverable-gate.sh`: он матчит ту же подстроку `gh +issue +create`, поэтому даже **no-op** `echo` с этой фразой требует маркера `# code-issue:` — учитывать при тестах/документации (или добавлять оба маркера).
