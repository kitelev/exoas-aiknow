# Retrieval: знания по концептам промпта (`$concepts`)

Второй запрос графового пути retrieval (RFC 9d5ffe26 v3, §Архитектура п. 1; фаза 1 программы 204e2439). Потребитель — второй слой (модель через Gate 0: `/context-loader`, `/knowledge-search`), не хук: `exocortex-cli run-query <uid> --vault <узкий mount exoas-aiknow> --format json --param concepts=<UID концептов через запятую>`.

Параметр `$concepts` — список UID концептов промпта, подставляется `NamedQueryRunner` экранированным строковым литералом; фильтр — `CONTAINS` по литералу-списку. Фильтра реестра здесь нет: субъект — любой ассет с ребром `aiKnow__Memory_aboutConcept` (domain свойства — aiKnow MemoryReference / MemoryFeedback / MemoryProject), объём выдачи задаёт сам запрос (решение фаундера R2).

Выход — строки `(asset, label, concept, fanout)`: `asset` — IRI знания, `label` — его метка, `concept` — UID концепта (или локальное имя при symbolic-форме), `fanout` — число ВСЕХ ассетов с ребром на этот концепт (широта концепта по корпусу знаний). Формы объекта ребра снимаются теми же двумя ветвями `BIND`, что и в запросе правил: хвост `<uid>.md` у file-IRI (с путём и беспутевой) и хвост после `#` у symbolic-формы.

```sparql
PREFIX aiKnow: <https://exocortex.my/ontology/aiKnow#>
PREFIX exo: <https://exocortex.my/ontology/exo#>
SELECT ?asset ?label ?concept ?fanout WHERE {
  ?asset aiKnow:Memory_aboutConcept ?c .
  ?asset exo:Asset_label ?label .
  BIND(IF(CONTAINS(STR(?c), "#"),
          REPLACE(STR(?c), "^.*#", ""),
          REPLACE(STR(?c), "^.*/([^/]+)\\.md$", "$1")) AS ?concept)
  FILTER(CONTAINS($concepts, ?concept))
  {
    SELECT ?c (COUNT(DISTINCT ?r) AS ?fanout) WHERE {
      ?r aiKnow:Memory_aboutConcept ?c .
    } GROUP BY ?c
  }
}
ORDER BY ?asset
```
