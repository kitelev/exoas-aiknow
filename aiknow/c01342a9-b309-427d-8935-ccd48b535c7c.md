## §A1 Addendum 2026-07-13 — Telegram Desktop через computer-control (реплаи / цитаты / удаление / отправка)

Механика набора и отправки сообщений в Telegram Desktop (native macOS app) через `mcp__computer-control__computer` (не браузер):

- **Отправка:** `key return` шлёт сообщение; **`key shift+enter` — перенос строки** внутри сообщения. Многострочное с пустой строкой = para1 → shift+enter ×2 → para2 → return.
- **Реплай на ЦЕЛОЕ сообщение (надёжно):** правый клик по сообщению → в контекст-меню «Reply» → плашка «Reply to …» над полем → **печатать текст НАПРЯМУЮ** (input авто-фокусится после Reply). ⛔ НЕ кликать отдельно в поле ввода после Reply — лишний клик в input **сбрасывает привязку реплая** (плашка «Reply to…» исчезает, уйдёт обычным сообщением). Verify перед `return`: плашка «Reply to…» + текст оба на месте.
- **⚠ Цитата-ФРАГМЕНТ (выделенный кусок) через drag — НЕНАДЁЖНА.** Telegram-выделение текста мышью **не прилипает к границам слов** (character-precise): `left_click_drag` то режет по середине слова (уходит обрезанная цитата «…циями … в одном ме»), то перевыделяет пол-сообщения. `double_click` снапит слово целиком, но computer-control **не умеет shift+click** (нет модификатора у `left_click`) → расширить word-selection нечем. **Вывод: для чистой цитаты — реплай ЦЕЛЫМ сообщением** (правый клик → Reply), фрагмент-цитату («Quote & Reply» после выделения) использовать только если готов к кривому выделению. Механика фрагмента (если всё же надо): выделить текст → правый клик по выделению → «Quote & Reply».
- **Удаление своего сообщения** (напр. ушло с кривой цитатой): правый клик → «Delete» → диалог «Do you want to delete this message?» с чекбоксом **«Also delete for <peer>»** (обычно уже отмечен) → «Delete». Это НАТИВНЫЙ диалог (не JS-alert) — кликается computer-control'ом. ⛤ Удаление у обоих — outward/необратимо: подтверждать с пользователем перед этим (третье лицо видит правку чата).
- **Edit не меняет цитату:** «Edit» правит только ТЕКСТ сообщения, привязку-реплай/цитату изменить нельзя → для смены цитаты только Delete+переотправка.
- **Идентификация чата:** папки-фильтры слева (Const/Peoples (N)/…); открыть профиль — клик по имени в шапке (bio, @username, «Add to contacts» = не в контактах); фото на весь экран — клик по аве в профиле, листать `key left/right`. Дисциплина ввода — verify-then-poll ([[gui-input-verify-then-poll]]): скриншот перед КАЖДОЙ отправкой (текст + реплай-плашка корректны; вдруг собеседник дописал ещё).
- **⛤ Копировать моноширинный `code`-спан (напр. bot-токен из @BotFather) = ОДИНОЧНЫЙ клик по спану → clipboard → `pbpaste`.** ⛔ НЕ транскрибировать секрет/токен со скриншота (0/O, l/I, 1/l путаются, один неверный символ = битый токен). В Telegram Desktop клик по `code`/`pre`-спану копирует его точь-в-точь; `pbpaste` в Bash даёт значение. Валидировать по назначению (bot-токен → `getMe`), потом **очистить буфер** (`printf '' | pbcopy`). Тот же клипборд-приём, что [[reverse-image-search-via-clipboard]] для картинок. Целиться точно в строку спана (промах на соседнюю строку → скопируется не то; verify длину/форму `pbpaste` перед использованием). ⛤ **Одиночный клик копирует ТОЛЬКО `code`/`pre`-спан; PLAIN-текстовый токен (юзер вставил как обычный текст, не код-блок) одиночным кликом НЕ копируется** (`pbpaste` вернёт не то) → **right-click по сообщению → «Copy Text»** (копирует весь текст сообщения; если сообщение = только токен, получаешь ровно его).
