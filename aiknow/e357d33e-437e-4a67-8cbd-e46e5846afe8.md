# Headless `claude -p` из хука/бота: статусы `rate_limit_event`, `--verbose` для stream-json, `--name`, убийство по pid — контракт, замеренный живым вызовом

## Принцип

Вызов `claude -p` из своего процесса (хук, бот, измеритель) — внешний контракт CLI, который стаб не покрывает по построению (он подменяет весь argv), а RFC описывает по памяти: `rate_limit_event.status` имеет ≥3 значения (`allowed` · `allowed_warning` — ответ ДОСТАВЛЕН при квоте ≥ порога предупреждения · `rejected`; `resetsAt` в epoch-секундах), `--output-format stream-json` под `-p` требует явного `--verbose`, `--name <n>` гасит побочный title-вызов и стаб-транскрипт, а pid из файла-маркера убивать только точным токеном + временем старта + `os.kill`.
Отказом считать ТОЛЬКО `status ∉ {allowed, allowed_warning}`; форму argv запирать осью без запуска + ≥1 живым вызовом той же формой ДО включения в проде.
Разбор — в теле в графе (см. оглавление).

## Когда правило срабатывает

Пишешь/ревьюишь код, зовущий `claude -p` (`--output-format json|stream-json`) из хука, poll-демона, измерителя; читаешь `rate_limit_event`/`usage` ответа; реконструируешь/убиваешь дочерний `claude` по pid из state-файла.

## ⛤ Замеры 2026-09-15 (ф3 RFC d9e70ca4, CLI 2.1.170; каждое число — с командой в отчёте узла `324178e3`)

- **`allowed_warning`** — 205 из 205 живых вызовов haiku при 7d ≥ 80 % вернули его ВМЕСТЕ с ответом (27–75 output-токенов, api 1.3–3 с); буквальное «≠ allowed ⇒ латч до `resetsAt`» захлопнуло бы пилот до сброса 7d-окна (≈ 15 ч) на первом промпте. `rejected` — 0. Механизм по бинарю: статус эмитится из заголовков `anthropic-ratelimit-unified-*` по порогам utilization; `resetsAt − Date.now()/1000` ⇒ секунды.
- **`--verbose`**: бинарь 2.1.170 при `-p --output-format stream-json` без него печатает `Error: When using --print, --output-format=stream-json requires --verbose` и выходит rc=1; `verbose` резолвится из флага, иначе из `viewMode`/`settings("verbose")`, а `--setting-sources ""` отрезает settings ⇒ живые вызовы держатся на локальной конфигурации, пока флаг не явный. `stream-json` на мёртвом хосте стримит `api_retry` через 0.6/1.7/3.8 с (⇒ `network` различим в бюджете хука), `json` ретраит ≈ 3 мин молча до rc=1.
- **`--name rsr-stage-a`**: title-вызов 0 и стаб-`.jsonl` 0 в 10/10; без него — стаб 10/10 и title-вызов 467–680 токенов в 8/10 (`modelUsage.inputTokens − usage.input_tokens`). `cache_creation` — только `ephemeral_1h` ⇒ TTL кэша системного промпта 1 ч, промахи при паузах > 60 мин.
- **Убийство по pid из маркера**: needle-подстрока `claude` матчит 33 живых процесса (пути `~/.claude/hooks/*`, `python3 ~/.claude/bin/*`, интерактивные сессии), 9 из них — лидеры групп ⇒ протухший маркер + wrap PID = `SIGKILL` группе чужой сессии. Floor: в маркер писать старт внука (`ps -o lstart=`), сверять ±15 с; матчить `--system-prompt`+имя модели (или basename стаба); только `os.kill(pid)`, никогда `killpg` по pid из файла; `killpg` — лишь над живым `Popen(start_new_session=True)`.
- **Harness-слепота**: стаб `RSR_MODEL_CMD` подменяет ВЕСЬ argv ⇒ боевая форма не исполняется ни одной осью (`integration-test-revert-verify` §A59) ⇒ ось на форму argv без запуска (A145) + 3 живых вызова той же формой; `communicate()` после kill — с таймаутом; порча латч-файла (`streak:"abc"`, `Infinity`) ⇒ `except (TypeError, ValueError, OverflowError)`, иначе rc=1 на каждом промпте.
