# Headless `claude -p` из хука/бота: статусы `rate_limit_event`, `--verbose` для stream-json, `--name`, убийство по pid — контракт, замеренный живым вызовом

## Принцип

Вызов `claude -p` из своего процесса (хук, бот, измеритель) — внешний контракт CLI, который стаб не покрывает по построению (он подменяет весь argv), а RFC описывает по памяти: `rate_limit_event.status` имеет ≥3 значения (`allowed` · `allowed_warning` — ответ ДОСТАВЛЕН при квоте ≥ порога предупреждения · `rejected`; `resetsAt` в epoch-секундах), `--output-format stream-json` под `-p` требует явного `--verbose`, `--name <n>` гасит побочный title-вызов и стаб-транскрипт, а pid из файла-маркера убивать только точным токеном + временем старта + `os.kill`.
Отказом считать ТОЛЬКО `status ∉ {allowed, allowed_warning}`; форму argv запирать осью без запуска + ≥1 живым вызовом той же формой ДО включения в проде.
Разбор — в теле в графе (см. оглавление).

## Когда правило срабатывает

Пишешь/ревьюишь код, зовущий `claude -p` (`--output-format json|stream-json`) из хука, poll-демона, измерителя; читаешь `rate_limit_event`/`usage` ответа; реконструируешь/убиваешь дочерний `claude` по pid из state-файла.

## ⛤ Замеры 2026-09-15 (ф3 RFC d9e70ca4, CLI 2.1.170; каждое число — с командой в отчёте узла `324178e3`)

- **`allowed_warning`** — 205 из 205 живых вызовов haiku при 7d ≥ 80 % вернули его ВМЕСТЕ с ответом (27–75 output-токенов, api 1.3–3 с); буквальное «≠ allowed ⇒ латч до `resetsAt`» захлопнуло бы пилот до сброса 7d-окна (≈ 15 ч) на первом промпте. `rejected` — 0. Механизм по бинарю: статус эмитится из заголовков `anthropic-ratelimit-unified-*` по порогам utilization; `resetsAt − Date.now()/1000` ⇒ секунды.
- **`--verbose`**: бинарь 2.1.170 при `-p --output-format stream-json` без него печатает `Error: When using --print, --output-format=stream-json requires --verbose` и выходит rc=1; `verbose` резолвится из флага, иначе из `viewMode`/`settings("verbose")`, а `--setting-sources ""` отрезает settings ⇒ живые вызовы держатся на локальной конфигурации, пока флаг не явный. `stream-json` на мёртвом хосте стримит `api_retry` через 0.6/1.7/3.8 с (⇒ `network` различим в бюджете хука), `json` ретраит ≈ 3 мин молча до rc=1.
- **`--name rsr-stage-a`**: title-вызов 0 и стаб-`.jsonl` 0 в 10/10; без него — стаб 10/10 и title-вызов 467–680 токенов в 8/10 (`modelUsage.inputTokens − usage.input_tokens`). `cache_creation` — только `ephemeral_1h` ⇒ TTL кэша системного промпта 1 ч, промахи при паузах > 60 мин.
- **Убийство по pid из маркера**: needle-подстрока `claude` матчит 33 живых процесса (пути `~/.claude/hooks/*`, `python3 ~/.claude/bin/*`, интерактивные сессии), 9 из них — лидеры групп ⇒ протухший маркер + wrap PID = `SIGKILL` группе чужой сессии. Floor: в маркер писать старт внука (`ps -o lstart=`), сверять ±15 с; матчить `--system-prompt`+имя модели (или basename стаба); только `os.kill(pid)`, никогда `killpg` по pid из файла; `killpg` — лишь над живым `Popen(start_new_session=True)`.
- **Harness-слепота**: стаб `RSR_MODEL_CMD` подменяет ВЕСЬ argv ⇒ боевая форма не исполняется ни одной осью (`integration-test-revert-verify` §A59) ⇒ ось на форму argv без запуска (A145) + 3 живых вызова той же формой; `communicate()` после kill — с таймаутом; порча латч-файла (`streak:"abc"`, `Infinity`) ⇒ `except (TypeError, ValueError, OverflowError)`, иначе rc=1 на каждом промпте.

## ⛤ Замеры 2026-09-16 (VL-28, child rsrhuman; ЧЕМ отличить headless `claude -p` от интерактива ИЗ ХУКА/ПОДПРОЦЕССА)

- **`CLAUDE_CODE_ENTRYPOINT` в env хуков и Bash-тула — ставит САМ claude:** `sdk-cli` при `-p|--print|--init-only|--sdk-url|!stdout.isTTY`, `cli` у интерактивного TUI (2.1.261 `T(e)`: `a.set("CLAUDE_CODE_ENTRYPOINT", e?"sdk-cli":"cli")`; унаследованный `cli` при `-p` переписывается в `sdk-cli`; иные унаследованные значения — `remote`, `sdk-ts`… — проходят как есть). Замер 2.1.170: `env -i … claude -p ok --settings <дамп-хук>` ⇒ в env хука `sdk-cli`; TUI-проба в tmux ⇒ `cli`. ⇒ признак «headless» для хука — `ENTRYPOINT != cli`; в env процесса `claude` (`ps -E`) переменной нет — она для потомков.
- ⛔ **`CLAUDE_CODE_CHILD_SESSION=1` стоит у ВСЕХ подпроцессов claude**, включая top-level TUI без ORCH_TARGET/CHILD_NAME (TUI-проба, `main-27887`) — признаком дочерней сессии НЕ является (детектор `concept-collision.child_session()` на нём ложен — задача `2568b1f5`). Дочерняя сессия оркестратора — только `ORCH_TARGET`/`CHILD_NAME` в env (их экспортирует `spawn-session.sh`; у 2 child есть, у 3 top-level нет).
- **stdin-JSON UserPromptSubmit:** `session_id`, `transcript_path`, `cwd`, `permission_mode` (`default` у `-p`; `bypassPermissions` у `--dangerously-skip-permissions`), `hook_event_name`, `prompt`; у TUI ещё `scratchpad_dir`, `prompt_id`. Хук — прямой потомок процесса `claude` (ppid = pid claude; `ps -o tty=,args= -p $PPID` даёт tty `??` у launchd-ботов и argv с `-p`). `/dev/tty` недоступен (ENXIO) у ОБОИХ — хуки без controlling tty; `os.isatty` false везде.
- **Дамп-хук как измеритель:** `claude … --settings <файл с hooks.UserPromptSubmit=[python3 dump.py]>` сливается с user-хуками ⇒ один промпт (`ok`) даёт stdin/env/ppid-цепочку ЖИВОГО хука; для TUI — detached tmux + `send-keys 'ok' Enter` + `/quit`; `RSR_JOURNAL`/`RSR_PROBE_OUT` в env изолируют журналы. Промпт `ok` классификатор считает `origin=human`.
- **Кто зовёт `claude -p` под ОБЩИМ `~/.claude` (хуки у них запускаются):** `rate-snapshot-refresh.sh` (`-p ok`, cwd `/`, каждые 20 мин при протухшем снимке), `auto-backup.sh` (07:30, cwd `~/dotfiles`, промпт 27 КБ — `origin=human` в журнале), `rules-barrier-probe.py`. 5 poll-ассистентов — изолированный `CLAUDE_CONFIG_DIR` (`~/.olya-claude` …), UserPromptSubmit-хуков там 0.

## ⛔ A/B-замер цены корпуса: три грабли, каждая даёт ПРАВДОПОДОБНО НЕВЕРНОЕ число

Метод (замерен 2026-09-21): фикстурный `HOME` (пустой каталог + симлинк
`~/.claude/.credentials.json`) → `claude -p 'Reply with exactly: ok' --model claude-haiku-4-5-…
--output-format json`; цена корпуса = дельта `input + cache_creation + cache_read` между прогоном
без него и с ним. Канарейка метода: правило с `paths:` обязано дать дельту ≈ 0 при живой дельте
у безусловного.

- ⛔ **HOME обязан быть СВЕЖИМ на КАЖДЫЙ замер.** Повторный прогон в том же HOME даёт **+4.8k**
  из накопленного состояния (20 301 → 25 207 на пустом корпусе) — то есть «цена правила»
  приобретает чужое слагаемое, и сравнение двух замеров становится бессмысленным.
- ⛔ **cwd обязан быть ТЕМ ЖЕ и уже «прогретым».** В НЕДОВЕРЕННОМ каталоге (`~/Developer`, любой
  новый) прогон виснет на trust-диалоге и возвращает пустой stdout при rc=0 — не JSON, ноль
  токенов. ⚠ Это ограничивает любой A/B **в рабочем дереве**, а не только этот замер.
- ⛔ **Серия виснет от ОСИРОТЕВШИХ прошлых вызовов.** Симптом резкий: вручную прогон идёт 3 с, из
  скрипта — таймаут 400 с. Дискриминатор — `ps -eo pid=,etime=,command= | grep '[c]laude -p'`
  (у меня было 4 висящих); лечение — `pkill -f 'claude -p'` перед серией.
- ⚠ **stdout — в ФАЙЛ, не в pipe:** `capture_output=True` ждёт закрытия pipe всеми держателями, а
  `claude` оставляет ребёнка ([[self-authored-claim-loses-its-provenance]] §A53).
- ⛤ **Модель контекста ограничивает предмет:** haiku-4-5 (200K) не вмещает корпус правил целиком
  (`Prompt is too long` при ~266k) ⇒ мерить группами и складывать, либо брать 1M-модель.
