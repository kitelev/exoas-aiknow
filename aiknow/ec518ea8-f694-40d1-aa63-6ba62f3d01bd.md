# Норматив объёма мобильного профиля: держать КОЛИЧЕСТВО ассетов, а не искать причину тормозов

## Принцип (директива Андрея 2026-08-05)

Когда мобильное устройство плохо ведёт себя с vault (перезагрузки Obsidian, долгая переиндексация, Jetsam) — **не искать причину**: расследование затягивается и сильно зависит от устройства. Вместо этого держать **норматив количества ассетов** в смонтированном профиле; чем меньше, тем лучше.

| Зона | Ассетов в мобильном профиле |
|---|---|
| **оптимально** | ≤ 3 000 |
| **допустимо** | ≤ 5 000 |
| **опасно** | ≤ 7 000 |
| только для компьютера | > 7 000 |

**Превышение — самодостаточное основание для разгрузки.** Причинно-следственную связь с конкретным симптомом устанавливать НЕ требуется: норматив — это бюджет, а не диагноз.

Норматив **переиспользуем**: применяется к любому мобильному профилю (личный, Олин, общий) и к любому будущему решению «домонтировать ли ещё один ассетспейс».

## ⛔ Инструмент замера — счёт ФАЙЛОВ, а НЕ SPARQL

SPARQL по `exo__Instance_class` **систематически завышает**: класс считается и под file-IRI, и под symbolic-IRI проекцией (symbolic-дуалы, см. `sparql-iri-form-pre-verify`). Замер 2026-08-05: `exo#Class` — SPARQL **661**, файлов на диске **427**.

```bash
find <vault>/assetspaces -name '*.md' -type f | wc -l          # объём профиля
for d in <vault>/assetspaces/*/*/; do                          # разбивка
  echo "$(find "$d" -name '*.md' -type f | wc -l) $(basename "$d")"; done | sort -rn
```

⚠ **Перед замером — `exosync pull`.** Локальный vault может отставать на тысячи файлов, и тогда бюджет считается по устаревшему состоянию. Эмпирика: vault-my отставал на **2193** файла; замер до pull дал 9062, после — 8928.

⚠ **Профиль ≈ весь vault.** Транзитивное `dependsOn`-закрытие делает эффективный набор равным ~100 % файлов vault (`mount-cost-is-dependson-closure-not-floor`) ⇒ счёт по смонтированному vault и есть объём на устройстве. По той же причине **«облегчённый профиль» как рычаг не работает** (0.7 %) — нужен физический раскол ассетспейса, а не конфигурация.

## ⛤ Разовая миграция НЕ решает задачу — считай запас хода

Бюджет — величина, которую **съедает рост**. Прежде чем предлагать миграцию, замерь темп и переведи его в месяцы запаса:

```bash
# прирост по exo__Asset_createdAt, только по ОСТАЮЩЕМУСЯ набору
# (валовый прирост vault ≠ прирост того, что живёт на телефоне)
```

- ⛔ **Мерить прирост ОСТАЮЩЕГОСЯ набора, а не всего vault.** Валовый прирост включает то, что и так уезжает в холод; он завышает тревогу. Эмпирика: vault-my растёт на **726 файлов/мес** валово, но остающийся набор — на **319/мес**.
- **Запас хода = (порог − остаток) / прирост остающегося.** Если он меньше ~12 месяцев — миграция обязана сопровождаться **регулярным процессом** (`exocortex-cold-archive-assetspace` ежемесячно), иначе это отсрочка, а не решение.
- **Формулировать вслух:** «план даёт N файлов и M месяцев запаса» — второе число решает не меньше первого.

## ⛤ Более ШИРОКИЙ вынос обычно ДЕШЕВЛЕ узкого — считай цену, не угадывай

Интуиция «вынести минимально необходимое» здесь **вредна**. Цена выноса = входящие ссылки из **остающихся** файлов; расширяя разрез, уносишь и сами файлы-источники.

- **Floor:** для каждого кандидата-разреза считать **сколько рёбер пересечёт границу**, а не сколько файлов уедет. Оптимум ищется по первому числу.
- Эмпирика: вынос слоя знаний ломает **2263** ссылки; тот же вынос плюс пять дешёвых шагов — **1348** (на 40 % меньше при вдвое большем объёме).
- ⚠ Считать обе адресации: по UID **и** по basename (дневники, `period__Day` адресуются по имени файла).
- ⛤ **Ссылки в ТЕЛЕ (`exo:Asset_bodyLink`) — половина цены и реификацией не чинятся** (пришлось бы удалить ссылку из читаемого текста). Разделять каналы в отчёте, иначе цена занижается вдвое (`sparql-iri-form-pre-verify` §Addendum 2026-08-05).

## ⛔ Что НЕЛЬЗЯ выносить ради бюджета

- **TBox (class/property-дефиниции) из shared-ассетспейсов.** `exoas-public` / `exoas-shared-*` монтируют и другие vault; вынос убьёт там резолв классов — ассет без своего class-TBox молча теряет тип, команды перестают резолвиться (`sparql-iri-form-pre-verify` §Addendum 2026-07-27). Замер 2026-08-05: из 125 TBox-ассетов слоя знаний безопасно движимы **12**, и те ломают **21 class-ссылку** — отрицательный размен.
- **Командную машинерию** (`exocmd__*`) — без неё исчезают кнопки.
- **Связанные пары врозь.** Дневники ссылаются на `period__Day`: вынести вторые, оставив первые, — единственный шаг из плана, который цену **увеличивает**.
