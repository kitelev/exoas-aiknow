# Vault Operations

## Floor — wikilinks
- Только проверенные UUID (hook validate-wikilinks.sh блокирует невалидные)
- Ручная проверка: `find /Users/kitelev/vaults/vault-my /Users/kitelev/vaults/vault-tbank /Users/kitelev/vaults/vault-exodev -name "<uuid>.md"`
- ✅ **Существование, от которого зависит запись, проверять в ЦЕЛЕВОМ vault**; для общих ассетспейсов (`exoas-public`, `exoas-exocmd`) авторитет — **remote**: `gh api "repos/kitelev/<as>/contents/<ns>/<uid>.md?ref=main" --jq .sha` (404 = удалён, что бы ни лежало локально).
- ✅ **Floor: аудит НЕсуществования ведёт индекс по `find ~/vaults` (широкая область), а вердикт о ЗАПИСИ по-прежнему по целевому vault.** Требования противоположны, и это надо развести явно — один перечень обслужить оба не может.
- ⛤ Механизм обеих ⛔-строк (15 неканоничных реплик в `~/vaults`; асимметрия монтирования) — разделы «⛔ ПЕРЕЧИСЛЕНИЕ ТРЁХ VAULT …» и «⛔ ЗЕРКАЛО floor'а …» в графе (оглавление роутера).

Это **отстающие реплики по построению**: удаление, уже применённое на remote и в каноничных vault, доезжает до них позже. Замер 2026-08-13 на удалённом `ems__EffortStatusToDo` (`6a0e933a`): каноничные три → **0** (верно), `~/vaults` → **15** (ложь).
  - ⚠ **Ошибка тихая и правдоподобная:** «файл найден» выглядит как успешная проверка, и дальше ты уверенно ставишь ссылку на несуществующий ассет. Отказал только `create`, валидирующий wikilink **по целевому vault** — то есть спас механический гейт, а не проверка.
  - ⛤ **Это ЗЕРКАЛО задокументированного mount-drift.** Известный класс — «ассета нет в ЭТОМ vault, хотя он существует» (`exocortex-cold-archive-assetspace`, `exosync-quarantine-triage`); здесь обратное — «ассет есть в реплике, хотя он УДАЛЁН». Оба лечатся одним: спрашивать **тот vault, куда пишешь**, а не «хоть где-нибудь».

## ⛔ ЗЕРКАЛО floor'а выше: для АУДИТА «ссылка битая» три каноничных vault — НЕДОСТАТОЧНАЯ область

- ⛔ **ЗЕРКАЛО floor'а выше: для АУДИТА «ссылка битая» три каноничных vault — НЕДОСТАТОЧНАЯ область, и ошибка идёт в ЛОЖНО-ПОЛОЖИТЕЛЬНУЮ сторону.** Floor выше защищает **запись** (там широкая область врёт «файл есть»); у **аудита несуществования** направление обратное: узкая область врёт «файла нет». Один и тот же перечень верен для первого и ложен для второго.
  - ⛤ **Механизм — намеренная асимметрия монтирования, а не рассинхрон:** `exoas-shared-private/…/to-exodev` смонтирован в бот-vault и **не** в `vault-exodev`; холодный архив (`exoas-my-archive`) живёт только в `vault-my-full` и бот-vault. Ссылка на такой ассет **валидна** и выглядит битой ровно потому, что ты индексировал не там.
  - ⚠ **Симптом-tell, ловится ДО вывода:** «битые» UID кучкуются в один класс (все — `Концепт: [[…]]`, все — ключи памяти, все — архивные). Настоящие висячие ссылки так не группируются.
  - ✅ **Floor: аудит НЕсуществования ведёт индекс по `find ~/vaults` (широкая область), а вердикт о ЗАПИСИ по-прежнему по целевому vault.** Требования противоположны, и это надо развести явно — один перечень обслужить оба не может.
  - ⛤ **Замер 2026-08-31 (пилот, не тираж):** 119 Backlog-тикетов, 5 кандидатов, проверка каждого — **0 фантомов, 5/5 ложных**. Детектор не построен: при такой точности он давал бы 100 % шума. Настоящий класс ложного долга нашёлся соседним вопросом и покрыт `vteam-projection-drift.sh` Д4.

## Floor — версионирование знаний
- Знания НЕ редактируются — они версионируются
- Update → новый ассет с `exo__Asset_supersedes`
- Deprecate → старый с `exo__Asset_deprecatedBy`
- При поиске фильтруй deprecated: `FILTER NOT EXISTS { ?s exo:Asset_deprecatedBy ?newer }`

## Floor — createdAt Format
- ВСЕГДА ISO 8601 с компонентом времени: `2025-10-18T20:41:36`
- НИКОГДА `T00:00:00` или дата без времени

## Floor — File Movement (перемещение файлов)
- `git mv` — **ТОЛЬКО внутри ОДНОГО git-репо** (сохраняет историю)
- ⛔ **Каноничные vault git-free** (`vault-my`/`vault-tbank`/`vault-exodev` — tarball-mount + ExoSync, `.git` нет вовсе) ⇒ там обычный `mv`
- ⛔ **Через границу сабмодуля — обычный `mv`, НИКОГДА `git mv`** (он молча поглощает сабмодуль): `submodule-cross-boundary-move`
- ⛔ `shutil.move()` и прочие обходные методы — по-прежнему нет
