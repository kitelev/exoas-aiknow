## §A1 (Грабля 1) — недетерминированный флак загрузки плагина (QEMU+Chromium)

**Симптом:** «Obsidian ready!» логируется, но `app.plugins.plugins.exocortex` не появляется за 30-90с; иногда грузится с 1-й попытки, иногда фейлит 3-5 подряд. Состояние `{enabled:true, loaded:false}`, ноль `[ExocortexPlugin]` console-строк (onload не отработал).

**Root cause (community-verified):** Docker Desktop на Mac гоняет amd64 через QEMU; **Chromium требует `inotify` при старте, а QEMU его ломает**; плюс Chromium `zygote` крашит QEMU. Obsidian = Electron/Chromium → недетерминированный onload-фейл. Rosetta (`useVirtualizationFrameworkRosetta:true`) включён по умолчанию, но НЕ устраняет флак полностью.

**Mitigation — relaunch-retry wrapper (обязателен локально):**
```ts
const MAX_LAUNCH_ATTEMPTS = 8;        // флак per-launch; relaunch почти всегда recovers
const PLUGIN_LOAD_WAIT_MS = 60000;    // успешный load <30-40с; провал детектится быстрее
async function launchWithPlugin(vault, label) {
  for (let i = 1; i <= MAX_LAUNCH_ATTEMPTS; i++) {
    const L = new ObsidianLauncher(vault);
    await L.launch();
    const w = await L.getWindow();
    // force-reload если enabled-but-not-loaded: disablePlugin → enablePlugin
    // (plain enablePlugin на already-enabled — no-op, не recovers)
    if (await tryLoadPlugin(w, label, PLUGIN_LOAD_WAIT_MS)) return L;
    await L.close().catch(() => {});   // relaunch fresh Electron
  }
  throw new Error(`${label}: plugin failed after ${MAX_LAUNCH_ATTEMPTS} attempts`);
}
```
- Per-attempt wait короткий (60с): провальный attempt не «медленный», а absent → быстрый relaunch выгоднее долгого ожидания.
- Overall test timeout — щедрый (40+ мин под эмуляцией), т.к. retry × медленные git/network ops накапливаются.
- На CI retry просто не срабатывает (грузится с 1-й) — безвреден.


## §A2 (Грабля 2) — `FuzzySuggestModal` НЕ выбирается программно через Playwright/CDP

**Симптом:** picker открывается, фильтруется (`allTextContents()` показывает 1 совпадение), но ни `keyboard.press("Enter")` (даже после `ArrowDown`), ни `.suggestion-item.click()` НЕ триггерят `onChooseItem` → `onClose` резолвит null → команда early-return'ит (no-op). `Escape` при этом работает (dismiss). В существующих spec'ах выбор через picker НИКОГДА не тестировался — только Escape.

**Root cause (Obsidian docs):** нет публичного API выбрать suggestion программно; синтетический keyboard/click под CDP/эмуляцией не доходит до chooser-selection.

**Mitigation — обойти picker, вызвать реальный handler напрямую:** плагин часто экспонирует менеджер на инстансе (напр. `plugin.profileApplyManager` per Issue #3320). Вызови production-метод с нужным UID:
```ts
await w.evaluate((uid) => {
  const mgr = window.app.plugins.plugins.exocortex.profileApplyManager;
  window.__res = { done:false, error:null };
  mgr.applyProfile(uid).then(()=>window.__res.done=true).catch(e=>window.__res.error=String(e?.stack??e));
}, UID);
```
Это тот же production-путь, что зовёт Cmd+P-команда после picker'а; обходится ТОЛЬКО pure-UI выбор. Picker оставь для доказательства Cmd+P-discovery (открыть → assert элемент в списке → Escape). **Confirm-модалки (`Modal` с кнопками) драйвятся нормально** — кликаются `.mod-warning`/`.mod-cta`; флак только у fuzzy-picker.

**Диагностика throw vs no-op:** fire-and-forget метод пишет outcome в `window.__res`; poll его в disk-wait, чтобы отличить «applyProfile threw (error+stack)» от «completed no-op (done && нет результата на диске)» вместо непрозрачного timeout. Renderer `console.error` в evaluate НЕ захватывается launcher stdio — используй window-global.

### ⛔ Addendum 2026-06-15 — harness synthetic-input лимит ≠ реальный human-selection code-баг (тот же симптом «onClose резолвит null → no-op»!)

Симптом «picker-selection = no-op (onClose резолвит null)» имеет **ДВЕ независимые причины** — не путать:

1. **Harness synthetic-input лимит (выше)** — синтетический keyboard/click под CDP/QEMU не доходит до chooser-selection. Затрагивает ТОЛЬКО автотесты. Реальный пользователь не аффектится. Mitigation = обойти picker (вызвать handler напрямую).

2. **Реальный human-selection code-баг (#3563, v16.96.8)** — затрагивает ЖИВОЙ клик пользователя на десктопе. Root cause (verified против `obsidian.asar`): `SuggestModal.selectSuggestion` вызывает `this.close()` (→`onClose()`) **ДО** `onChooseSuggestion`→`onChooseItem`, оба синхронно в одном стеке. Промисифицированный modal, который синхронно `resolve(null)` в `onClose`, выигрывает гонку → последующий `onChooseItem` подавляется guard-флагом → `resolve(null)` → команда early-return'ит. **На mobile (`isPhone`) порядок РЕВЕРСИРОВАН** — `Modal.close` дефёрит `onClose` через `animateClose().then` (choose-before-close). **Fix-паттерн (order-independent):** `onChooseItem` только ЗАПИСЫВАет выбор (`this.chosen=item`); `onClose` дефёрит единственную резолюцию в `queueMicrotask(()=>resolve(this.chosen))` (запланирован ДО `super.onClose()`, чтобы пережить throw в teardown). Microtask бежит после синхронного `selectSuggestion`-стека → selection отдаёт item, Escape отдаёт null.

**Как различить при диагностике:** если user воспроизводит no-op **вручную** (живой клик/Enter) — это причина №2 (code-баг), НЕ harness. Если no-op только в автотестах, а DevTools-handler работает — причина №1 (harness). ⛤ **Тест для причины №2** должен драйвить РЕАЛЬНЫЙ порядок Obsidian (`onClose()` затем `onChooseItem()`, извлечён из `obsidian.asar`), НЕ звать `onChooseItem` напрямую (vacuous, маскирует баг — см. test-fixture-realism). revert-verify: баговый синхронный null-resolve → тест резолвит null (FAIL); фикс → резолвит item (PASS).


## §A3 (Грабля 3) — setup эфемерного git-vault для desktop apply-path

Desktop-команды плагина (apply-profile materialize) делают `git submodule add <url>` (клонируют), потом перезаписывают tarball'ом; нужен:
- **git-vault** (`git init` + initial commit), НЕ plain dir.
- **git-credentials для приватных репо:** `git config --global url."https://x-access-token:${PAT}@github.com/".insteadOf "https://github.com/"` (`stripGitEnv()` сохраняет HOME → плагинский git-subprocess читает `~/.gitconfig`). PAT в `.gitmodules` НЕ попадает (insteadOf — transport-only).
- **PAT в `data.local.json`** (`.obsidian/plugins/<id>/`) для tarball-pull (отдельно от git).
- **commit после bootstrap/add** — fs-move'нутые файлы untracked → Vision-Lock-#5 uncommitted-guard рефузит apply (untracked-dir видится git'ом как «1 uncommitted file»). `git add -A && commit` перед apply.
- **`.exocortex/` mkdir** — lock-менеджер пишет `.exocortex/switch-lock.json` без создания родителя → ENOENT на свежем vault.
- **relaunch между фазами** — bootstrap/add пишут на диск через `vault.adapter` (fs-move), metadataCache/triple-store НЕ переиндексируются автоматически; свежий launch = полный reindex → picker видит ассеты, apply резолвит DAG. Mirror'ит реальный alpha-UX «Reload Obsidian».
- **`.gitignore`** `.obsidian/` + `.exocortex/` (чтобы PAT/lock не закоммитились).


## §A4 (Грабля 4) — disk-assert, не dry-run; surface ошибки, не timeout

- Assert **реальную материализацию на диске** (`countMarkdown(dir) > before`), не модалку/нотис.
- Poll готовности triple-store перед apply — ⛔ **`count()` «стабилизировался» НЕ достаточно: первое плато ≈ 91 % триплов (Грабля 6) ⇒ гейтить на ПОЛНОТЕ, форсируя `sparql.refresh()` каждый poll** — `listAllAssetSpaceInfos()` читает его, а `convertVault` лагает за metadataCache.
- Materialize-poll щедрый (1200с под эмуляцией; 6 `git submodule add` + tarball pull) НО с early error-surface (см. Грабля 2) — throw ловится за секунды, не за 1200с.


## §A5 (Грабля 5) — create-instance кнопки в e2e (GUI-BDD release-gate)

Драйв create-instance кнопок (`Create Task` / `Create Project` / `Create Area` / `Create Meeting`) против РЕАЛЬНОГО published-контента в выделенном release-gate (НЕ в 6 required shards). Pattern: fresh ephemeral vault per run + **`git clone` 3 ПУБЛИЧНЫХ `exoas-*` repo** (exo+exocmd+public) → живые published команды/groundings/InheritanceRules → ловит регрессии published-контента (hermetic-фикстуры дали бы ложную уверенность — test-fixture-realism). Публичные repo → **без PAT** (GITHUB_TOKEN лишь снимает anon rate-limit) → suite никогда не self-skip'ит, гоняется на каждом push-to-main/nightly. Изоляция: `tests/e2e/eka-gui/` ВНЕ `tests/e2e/specs` → shard-validator не видит → не блочит PR.

Грабли drive create-instance (все verified PR #3583/#3585):
- **`confirmMessage` → НАТИВНЫЙ `window.confirm()`** (ObsidianCommandPromptAdapter). Под CDP Playwright по умолчанию **DISMISS** → команда bail'ит (no-op). Обязателен `page.on("dialog", d => d.accept())` ДО клика. Команды с confirm: "Create Project", "Create Meeting Instance".
- **Form-modal драйвится** (в отличие от FuzzySuggestModal): `DynamicFormModal`→React `DynamicForm`: input `.dynamic-form-input[data-testid="field-<name>"]` (fallback на первый text-input), submit `.dynamic-form .modal-button-container button.mod-cta`.
- **InheritanceRule-резолюция гонится за triple-store.** Первый клик на свежем vault может выстрелить grounding с пустым IR-списком → backlink (Effort_area/Effort_parent/Area_parent) НЕ записан, fallback на `exo__Asset_prototype`. Митигация: **retry open→click на ЛЮБОЙ transient** (button-not-render / form-raced / backlink-absent), re-open пере-резолвит против более-проиндексированного store. `waitForStoreSettled` + invalidate+refresh НЕ достаточно — surface late-indexed binding только re-OPEN (новый leaf) + время.
- **Backlink-ключ form-tolerant:** published InheritanceRules пишут ключ ЛИБО prefixed (`ems__Effort_area`) ЛИБО expanded-IRI (`https://exocortex.my/ontology/ems#Effort_area`) — per grounding. Матчить `/Effort_area/` (значение = source-uid — инвариант), НЕ `ems__Effort_area`.
- **"Create Project" кнопка резолвится МЕДЛЕННО+ВАРИАТИВНО** под Docker-индексацией (иногда >2 мин; Task/Area — быстро/надёжно). Retry лишь ждёт. **Митигация: избегать flaky-кнопку — SEED ассет целевого класса** (seed ems__Project → "Create Task on Project" через быструю Create Task), не создавать через медленную кнопку. Покрытие backlink'а сохраняется. (Root-кандидат slow-resolve: у Project много binding-вариантов → resolver finish'ит последним; дубликация exocmd∩public мала, не причина.)
- **Verify через CI-прогон, НЕ локальный Docker** (prompt-директива): push branch → workflow_dispatch/pull_request на нативном amd64 раннере (без QEMU). `workflow_dispatch` требует workflow на default-ветке → для нового workflow добавить paths-filtered `pull_request` триггер для pre-merge верификации.


## §A6 (Грабля 6) — `waitForStoreSettled` count-plateau ≠ store COMPLETE → assert в транзиентном load-окне (store-completeness race)

<!-- Added by /session-retrospective 2026-06-16 — root: eka-gui scenario 3 (#3587) "Create Project не рендерится" оказался НЕ logic-drop, а timing race: assert внутри окна неполного convertVault-store. -->

**Симптом:** create-кнопка (Create Project / иногда Create Task backlink-IR) интермиттентно отсутствует/неполна на fresh-vault, ДЕТЕРМИНИРОВАННО выглядит как «логический дроп конкретной кнопки», хотя резолвер корректен.

**Root (verify-before-assert, #3587):** на EKA-layout (`assetspaces/<owner>/exoas-*`) default `lazyBootstrapFolders` НЕ матчат (`startsWith`) → TBox не preload → command/binding/grounding-триплы грузятся ТОЛЬКО через `convertVault()` (инкрементально, против частично-распарсенного cold-start metadataCache). `waitForStoreSettled` (count стабилен 2 цикла) возвращается на ПЕРВОМ count-плато (~15060 из ~16512 триплов) — store ещё НЕ полон. Сценарий, ассертящий в этом окне, видит частичный store → `loadCommand(cmd)` возвращает NULL (grounding-subgraph не приземлился) → кнопка дропается. **Не Project-specific** — это гонка наполнения; Create Project «проигрывает» чаще (его subgraph приземляется позже). Доказано: 2 CI DIAG-раунда (round-1 count=15060 loadCommand=NULL; round-2 count=15089 loadCommand=OK) + Node convertVault-repro (полный store 16512 → resolveForAssetMulti ВОЗВРАЩАЕТ Create Project; CLI apply резолвит). Продукт eventually-consistent (re-render на store-settle wired post-#3580/v16.97.4) — баг в ТЕСТЕ.

**Mitigation (test-only gate):** перед сценариями гейти на ПОЛНОТЕ store, не на count-плато. `waitForCreateCommandsResolvable(window, seedAreaRel, classUid, [Create Task, Create Area, Create Project])` — каждый poll **ФОРСИТ `plugin.sparql.refresh()`** (re-index против дозревающего metadataCache) + `lazyAssetGraphLoader.clearAll()` + `commandResolver.invalidateCache()`, поллит `resolveForAssetMulti(seedAreaIRI, [classUid,"ems__Area","exo__Asset"])` до тех пор пока ВСЕ required-метки не зарезолвятся. ⛤ **`invalidateCache()` БЕЗ `refresh()` НЕ работает** — чистит только resolver-кэш, не STORE; поллинг одного и того же partial-snapshot таймаутит (первая версия gate упала ровно так). `refresh()` re-читает все файлы → store растёт до полноты.

**Диагностический приём (когда reasoning заходит в тупик «триплы есть, а loadCommand NULL»):** добавь временный DIAG-`test()` в spec, дампящий live-store через `window.evaluate` (`store.count()`, `resolveForAssetMulti`, `loadCommand`, `loadGroundingByUid`, raw-триплы по UID), push → CI eka-gui (native amd64) → читай `log()` из run-логов. Один-два DIAG-раунда дают ground truth store-vs-resolver-vs-render быстрее любых гипотез. (⚠ в минифицированном bundle `t.object.constructor.name==="IRI"` ненадёжен — esbuild манглит имена классов; ключуйся по ЗНАЧЕНИЯМ триплов, не по constructor.name.)

**Контрибьютор-root (отдельный issue):** bootstrap-folder EKA-mismatch → preload TBox glob — design trade-off (bootstrap scope vs cold-start speed), отложен post-alpha (#3588). Для fresh малых alpha-vault окно краткое → impact скромный.


## §A7 (Грабля 7) — авто-показываемый Modal на plugin onload перехватывает pointer events в общем content-rich e2e test-vault

**Симптом:** добавил новую фичу, которая **авто-показывает Modal на `onload`/`onLayoutReady`** (welcome-панель, what's-new, first-run wizard). **Root (verify-before-assert):** все e2e-shard'ы делят **ОДИН** `packages/obsidian-plugin/tests/e2e/test-vault/` (≈162 markdown-нот: Areas/Projects/Tasks/03 Knowledge), но **БЕЗ `assetspaces/`**. **Mitigation (production-гейт, НЕ test-infra-хак):** гейтить авто-показ на **«genuinely fresh vault»**, а не только «not-bootstrapped». Надёжный сигнал — счётчик нот: `app.vault.getMarkdownFiles().length <= FRESH_VAULT_MAX_NOTES` (1 — пустой vault или только сток `Welcome.md`). Канонический fresh-tester flow (install plugin → Bootstrap → …) стартует из пустого vault. Re-entry-команда (`Setup`) остаётся **всегда доступной** для тех, кого консервативный авто-показ пропустит → покрытие реальных fresh-testers не страдает, а content-rich/e2e vault'ы (162 > 1) больше не триггерят.
- ⛔ Альтернатива «seed `data.local.json` с suppressed-флагом в e2e test-vault» — отвергнута: чинит e2e, но НЕ чинит real-world false-positive; test-infra seed может протухнуть при refresh плагина в vault.
- ⛤ Гейт держать в pure-функции (`shouldShowFirstRunPanel(state, completed, markdownCount)`) → unit-тестируемая truth-table (включи строку «content-rich vault (162) → false»), revert-verify на CI.

**Как драйвить (verified PR #3659, eka-gui scenario 9):**
- Combobox-input: `[data-testid="field-<fieldName>"]` (fieldName = ключ из grounding `inputSchema.properties`, напр. `exo__Asset_isDefinedBy`). `.fill(query)` → React `onChange` → фильтрует + открывает dropdown (`.fill()` сам фокусит → `onFocus` тоже открывает).
- Option: `[data-testid="option-<fieldName>-<candidate.uid>"]` (uid = `exo__Asset_uid` кандидата, full UID). Wait-visible → `.click()`.
- ⛤ Option коммитит на **`onMouseDown`** (не click) с `e.preventDefault()` — Playwright `.click()` шлёт mousedown первым → коммит срабатывает, фокус не уходит (preventDefault гасит blur). Committed value = `"`<uid>`"` уходит в form values.
- Фильтр — **substring** (`label.toLowerCase().includes(query)`): query может вытащить несколько `$foo*`-соседей; **кликай конкретную option по UID-testid** (детерминизм), не полагайся на «единственный результат».
- Submit: `.dynamic-form .modal-button-container button.mod-cta`.
- Label-поле формы: `.dynamic-form [data-testid="field-label"]` (или fallback `.dynamic-form input.dynamic-form-input` `.first()` — label-input идёт первым в DOM).

**Co-location-проверка инстанса.** Если grounding = `create_instance` с `targetFolder=$isDefinedByFolder`: новый инстанс ложится в папку ВЫБРАННОЙ онтологии (`refToFolder`), `exo__Instance_class` = host-класс (через `$targetClassSelf`). ⛤ Чтобы доказать, что **picker реально драйвит** значение (а не копирует host'ово isDefinedBy) — выбирай онтологию **ОТЛИЧНУЮ** от host'ового isDefinedBy (напр. `$exo` на класс-def `ems__Task`, чей isDefinedBy=`$ems`); тогда co-located-папка отличается от host-папки = picker-эффект доказан. ⛤ Включай co-location-папку в **retry-accept predicate** хелпера (а не только в финальный assert): `resolveIsDefinedByFolder` молча fallback'ит на host-папку при `refToFolder=null` → инстанс с верным frontmatter но неверной папкой иначе будет accept'нут retry-циклом и затем hard-fail'нет folder-assert (flake вместо retry).

## §A9 (Грабля 9) — ссылка в блоке Properties **НЕ является `<a>`**: селектор с ограничением по тегу молча не матчит ничего

Wikilink в **теле** заметки рендерится Obsidian'ом как `<a class="internal-link">`, и рефлекс переносит эту форму на **frontmatter**. В блоке Properties элемент другой — `.metadata-link-inner.internal-link` (не анкер), поэтому `.metadata-container a[data-href]` даёт **ноль совпадений**, а поллер отдаёт `Timed out` — то есть симптом «фича не отработала» при **исправной** фиче.

- ✅ **Floor: селектор КОПИРУЕТСЯ из продового патча, а не выводится по аналогии.** Патч, который ты проверяешь, уже перечислил все формы, в которых его цель встречается (`PropertiesLinkPatch` селектит `.internal-link` **без** ограничения по тегу). Копируй его первую форму; если берёшь свою — она обязана быть **не уже** продовой.
- ⚠ **Симптом-tell, отличающий от настоящего провала:** в артефакте прогона (`error-context.md` / скриншот) искомый текст **ПРИСУТСТВУЕТ**. Значит рендер состоялся, и красный даёт **твой селектор**, а не продукт. ⛔ Не «чинить» продукт по такому красному, пока не посмотрел артефакт.
- ⛤ **Класс шире Properties:** копируя селектор из прода, легко взять его **третью** форму (fallback) вместо первой — набор форм там перечислен по убыванию специфичности. Бери перечисление целиком либо самую общую.
- ⛤ **Для дифференцирующего контроля «ссылка в теле vs во frontmatter» в ОДНОЙ заметке** нужны взаимоисключающие селекторы, иначе body-набор втянет frontmatter-элементы: `.markdown-preview-view .internal-link:not(.metadata-container .internal-link)` против `.metadata-container .internal-link, .metadata-container [data-href]`.
