# Виртуализованные списки в браузере: snapshot ≠ полнота — аккумулировать через скролл

## Принцип

Современные веб-ленты (YouTube playlists/videos grid, Twitter/X timeline, Gmail, бесконечные feed'ы, react-window/react-virtualized таблицы) **виртуализируют DOM**: в дереве в каждый момент держатся только видимые + несколько буферных элементов, остальные **выгружаются** и подменяются при скролле. Поэтому **`document.querySelectorAll(<карточки>)` возвращает ЧАСТИЧНЫЙ снимок** — лишь то, что сейчас в окне. Один такой снимок ≠ полное перечисление списка.

⛔ Любое **перечисление/инвентаризация** (сколько элементов, какие именно, «все ли N плейлистов») по одному `querySelectorAll` на виртуализованной ленте **систематически пропускает элементы** — без ошибки, тихо. Negative-claim «в списке N элементов» из одного снимка = ложь по построению (тот же класс, что `verify-before-assert` negative-existence из частичного источника).

## Когда правило срабатывает

- claude-in-chrome / computer-control: посчитать/перечислить элементы ленты (плейлисты, видео, письма, твиты, карточки).
- Решение зависит от ПОЛНОГО списка: «удали лишние», «найди X среди всех», «сколько всего».
- Сигнал виртуализации: контейнер с `overflow`, элементы с `position: absolute/translateY`, `react-window`/`virtual` в классах, число DOM-узлов «слишком ровное» (≈ размер окна), счётчик на странице > числа найденных узлов.

## Правильный паттерн

1. **Найди authoritative-счётчик, если есть.** Часто страница сама печатает «N плейлистов» / «N видео» / баннер «N недоступных видео скрыто» — это надёжнее DOM-обхода. Сверяй своё перечисление с ним.
2. **Аккумулируй по позициям скролла, а не один снимок.** Скролль шагами, на каждом — `querySelectorAll` → клади в `Set`/`Map` по стабильному ключу (href/videoId/data-id, НЕ по индексу — индексы переиспользуются), пока размер Set не перестанет расти (K скроллов подряд без новых = дно):
   ```js
   const seen = new Map();
   let stale = 0, prevSize = 0;
   while (stale < 3) {
     document.querySelectorAll('<селектор-карточки>').forEach(el => {
       const key = el.querySelector('a[href]')?.href;   // стабильный ключ, не индекс
       if (key) seen.set(key, el.textContent.trim());
     });
     window.scrollBy(0, window.innerHeight * 0.8);
     await new Promise(r => setTimeout(r, 600));          // дать ленте догрузиться
     stale = (seen.size === prevSize) ? stale + 1 : 0;
     prevSize = seen.size;
   }
   ```
3. **⛤ CDP-таймаут (~45s) на длинных циклах.** `javascript_tool` режется по таймауту на долгих скролл-loop'ах → дроби на короткие проходы (несколько вызовов по ~5-8 скроллов) ИЛИ синхронная экстракция без скролла, если лента УЖЕ догружена (после ручного/визуального прокручивания вниз).
4. **Визуальная сверка скриншотами.** На критичных перечислениях — пройди скриншотами (`computer` screenshot + scroll) и сверь визуально с накопленным Set: глаз ловит то, что снепшот пропустил.

## Запреты

- ⛔ Перечислять/считать элементы виртуализованной ленты одним `querySelectorAll` и заявлять это полным списком.
- ⛔ Ключевать накопление по индексу/позиции (виртуализация переиспользует) — только по стабильному ID (href/data-id).
- ⛔ Строить необратимое действие (удаление, массовая правка) на основе частичного снимка — сперва полный аккумулированный список + сверка со счётчиком/скриншотами.
