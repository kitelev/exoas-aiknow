## Разборы

## §A1 Empirical reference (2026-07-25 — some transitive advisories are UNRESOLVABLE via deps → ship the SAFE SUBSET + defer; and a monorepo dep-bump's "validated" claim MUST cover the packages that USE the bumped dep, not a convenient smoke)

Extends 2026-07-21. Not every npm-audit advisory has a clean fix, and `npm audit fix --force` is not a reliable escalation.

- **`fixAvailable:false` = there may be NO remediation path, even with `--force`.** A fresh `brace-expansion ≤5.0.7` advisory (GHSA-mh99-v99m-4gvg, 36 high) cascaded through the **dev toolchain** via nested old `minimatch` (eslint / jest / typescript-eslint). Reaching patched `brace-expansion@5.x` requires `minimatch@10` — which **removed the callable default export** (`require('minimatch')()`) that jest+babel coverage tooling (babel-plugin-istanbul / test-exclude, dep-internal, un-overridable) still calls that way. So the two requirements are **irreconcilable**: `minimatch@3.x` = callable API + vulnerable brace-expansion; `minimatch@10.x` = patched brace-expansion + broken coverage pipeline. `npm audit fix --force` was a **no-op** (`fixAvailable:false`); root-`overrides` (even on npm 11) left residuals — npm won't fully force a **workspace-nested** minimatch/brace-expansion.
- **When forcing is proven irreconcilable → ship the SAFE SUBSET + defer the rest to upstream.** Split the advisories: fix the cleanly-overridable / patch-bump ones (here `qs` override `^6.15.3`; `uuid` runtime dep `^13.0.0`→`^13.0.1`), **leave** the toolchain-cascade one (brace-expansion) for upstream (jest/babel/typescript-eslint will bump their minimatch usage). The non-required `npm-audit` check stays red on the residual highs, but the runtime vuln is closed and the test pipeline is NOT regressed. `--force` and clever override-gymnastics that break the build are worse than a documented partial + defer.
- **⛤ A monorepo dep-bump's local "validated" claim MUST exercise the packages that USE the bumped dep — a core-only smoke lies.** Forcing `minimatch@10`/`glob@11` passed local `check:types`+`lint`+`build`+a **core** jest smoke+a cli smoke — but broke ALL 6 `test-coverage-shard` + `test-coverage-cli` in CI (`minimatch is not a function`). The break was in the **obsidian-plugin** coverage/transform pipeline, which the core-only smoke never ran. Floor: before claiming a major dep bump "safe", **grep the bumped dep's consumers** (`grep -rl minimatch packages/*/src`; but ALSO the transform tooling that uses it internally) and run the **plugin + cli** jest suites, not just core — or accept CI as the authoritative gate and don't assert "validated" from a partial local run (sibling [[test-fixture-realism]] "green units ≠ behaviors it doesn't measure", verify-before-assert "authoritative = CI"). Arming an auto-merge + a merge-watcher (per [[event-driven-coordination]] + [[ci-watch-check-runs-not-rollup]]) caught the required `test-coverage` failure and blocked the merge → fix-forward with the safe subset; nothing broken shipped.

## §A2 ⛤ Empirical reference (2026-08-07 — ⛔ в npm-WORKSPACE монорепо вход `npm audit` = КОРНЕВОЙ `package-lock.json`; `cache-dependency-path` — это ключ кэша setup-node, НЕ вход аудита; на этой подмене Dependabot 3 суток чинил не тот лок)

Секции выше отвечают на «**чем** чинить» (deps-bump, split-exposure, `--omit=dev`). Недостающая половина — «**что именно** аудит читает». Ошибка здесь стоит не лишнего коммита, а **дней** красного гейта: правки уходят в файл, который аудит не смотрит.

**Механизм.** Джоб гоняет `npm audit --audit-level=high --omit=dev` с `working-directory: packages/core`. `packages/core` — **workspace-член** (корневой `package.json` объявляет `workspaces: ["packages/*", …]`), поэтому npm **поднимается вверх** к корневому `package-lock.json`. Член-лок входом аудита **не является**.

⛔ **Ловушка — соседняя строка того же джоба:**
```yaml
- uses: actions/setup-node@v4
  with:
    cache: "npm"
    cache-dependency-path: packages/core/package-lock.json   # ← КЛЮЧ КЭША, не вход аудита
- run: npm audit --audit-level=high --omit=dev
  working-directory: packages/core                            # ← отсюда npm идёт в КОРНЕВОЙ лок
```
Обе строки называют `packages/core`, и первая **прямо указывает на член-лок** — поэтому «аудит смотрит сюда» читается как факт, а не как догадка.

- ⚠ **Дискриминатор дешёвый и однозначный: регенерация НЕ ТОГО лока даёт ZERO-DELTA.** `npm install --package-lock-only --ignore-scripts` в `packages/core` → `git diff --stat` **пусто**. Файл актуален относительно своего манифеста; он просто ни на что не влияет. Пустой diff там, где ждёшь фикс, = **ты не в том файле**, а не «нечего чинить».
- ⛤ **Следствие про Dependabot, объясняющее «почему никто не починил за 3 дня»:** PR Dependabot, сконфигурированного на `directory:` workspace-члена, трогает **member**-лок ⇒ **структурно неспособен** сдвинуть гейт. Такой PR мержится, выглядит осмысленно, гейт остаётся красным — и наличие открытого «фикса» ещё и **подавляет** расследование («да вот же его чинят»). Проверять `.github/dependabot.yml` `directory:` для npm-экосистемы отдельно.
- ⛔ **`private: true` НЕ выводит workspace-член из prod-графа аудита.** Он управляет **публикацией в npm**, а не классификацией в графе: `dependencies` приватного члена `--omit=dev` **видит**. Формулировка «пакет приватный ⇒ гейт его не требует» — ложный механизм.
- ✅ **Покрыт ли член — решает ТОПОЛОГИЯ корневого лока, а не флаг манифеста.** Нет вложенного `node_modules` ⇒ член резолвится в **hoisted**-узел, и бампа hoisted-узла хватает на всех таких членов разом:
  ```bash
  python3 -c "
  import json; L=json.load(open('package-lock.json'))['packages']
  print(*[(k,v.get('version'),v.get('dev')) for k,v in L.items() if k.endswith('/<dep>')], sep='\n')"
  ```
  `dev` не выставлен (`None`) ⇒ узел на **prod**-пути ⇒ его и флагует `--omit=dev`.

**Empirical:** 2026-08-07, PR #4034. `main` красный с 08-04 на `npm-audit-exocortex` (GHSA-5p4m-2wfm-xmqj, `js-yaml >=4.0.0 <4.3.1`) ⇒ Auto Release **skipped** на каждом мерже репо-wide; `d75eaa07` (parking-фича, merged 08-07) до пользователя не доехал. Начал с `packages/core/package-lock.json` — регенерация дала **ноль строк diff**, и именно этот ноль вскрыл подмену. В корневом локе `node_modules/js-yaml` = **4.3.0, `dev` не выставлен**. Фикс по split-exposure: `packages/cli` (единственный **публикуемый** prod-потребитель) `^4.2.0 → ^4.3.1` + `npm audit fix --package-lock-only` (non-force) → 2 файла, 39/39. Dependabot #4028 висел открытым с 08-04, трогая `packages/core/package-lock.json` — починить гейт не мог **по построению**. Итог: push-run `31146056045 completed/success` → auto-release `31146267370 completed/success` → **v16.214.0**; `compare d75eaa07...v16.214.0` = `ahead` (заблокированный мерж внутри). Cost детура ~1 регенерация; предотвращено — бесконечное ожидание Dependabot.

## §A3 ⛔ Addendum 2026-08-07 — ТОЧНЫЙ пин в `overrides` это пол И ПОТОЛОК: когда новая advisory накрывает запиненную версию, пин конвертируется из ФИКСА в БЛОКЕР — и молча, потому что подавляет ровно ту регенерацию, которая его бы починила

§Addendum 2026-07-27 (выше) **создал** пин `"brace-expansion@5.x": "5.0.8"` как фикс: он вытаскивал prod-путь из GHSA-mh99-v99m-4gvg. **2026-08-03** опубликована **GHSA-rgw5-rvv9-x895** (`high`, *«bypassing the CVE-2026-14257 mitigation»*) с диапазоном **`>= 4.0.0, < 5.0.9`** ⇒ **сам пин 5.0.8 стал уязвимым**, а патч `5.0.9` существует на реестре.

⛤ **Дефект не в том, что пин устарел — а в том, что он ДЕРЖИТ уязвимость.** Доказательство внутри одного лок-дифа (PR #4034, регенерация ради js-yaml):

| Узлы `brace-expansion` | Исход той же регенерации | Override |
|---|---|---|
| 1.x — **6 узлов** | `1.1.16 → 1.1.18` **автоматически** | нет |
| 2.x | `2.1.2 → 2.1.4` **автоматически** | нет |
| **5.x, prod-путь** `cli → glob@11 → minimatch@10.2.5` | **остался 5.0.8**, `dev` не выставлен | **есть**, exact `5.0.8` |

`1.1.18` и `2.1.4` — **ровно патч-версии этой же advisory** ⇒ npm её знает и увёл каждый узел, которому разрешили. Тот же пакет, тот же прогон, противоположные исходы; единственный дискриминатор — **точный пин**.

- ⛔ **Отказ тише обычного устаревания:** обычная stale-зависимость чинится следующей регенерацией. Здесь регенерация — это ровно то, что пин подавляет, поэтому дефект **самоподдерживающийся** и не рассосётся ни при одном будущем `npm install`.
- ✅ **~~ОТКРЫТЫЙ ВОПРОС~~ — ЗАКРЫТ 2026-08-07 (PR #4036). Кандидат ОПРОВЕРГНУТ; механизм — SCOPING ПРОД-ГРАФА ПО РАБОЧЕЙ ДИРЕКТОРИИ.** Вопрос стоял: почему `npm audit --audit-level=high --omit=dev` даёт **0** при живом уязвимом prod-узле. Кандидат «audit подавляет узлы, форсированные `overrides`» — **неверен**: замер по трём поверхностям **одного и того же лока** показал, что override-пиненный 5.0.8 флагуется **громко** везде, где достижим.

  | Поверхность | до бампа | после |
  |---|---|---|
  | корень репо | **2 high**, rc=1 | 0 |
  | `packages/core` — `working-directory` джоба | **0**, rc=0 | 0 |
  | `packages/cli` — публикуемый пакет | **2 high**, rc=1 | 0 |

  ⛤ **Механизм:** `packages/core` **не зависит** от `packages/cli`, поэтому `--omit=dev` вырезает цепочку `cli → glob@11 → minimatch@10.2.5 → brace-expansion` из его **достижимого** прод-графа. Лок один и тот же; различается **подмножество**, а не источник. ⇒ «сколько флагует audit» — функция **рабочей директории**, а не свойство лока. ⚠ Не путать с соседним §Addendum 2026-08-07 («вход `npm audit` = КОРНЕВОЙ лок»): там про то, **какой лок читается**, здесь — про то, **какая его часть достижима**. Обе оси нужны, и обе дают тихий ноль.
- ⛔ **Следствие дороже самого ответа: гейт СТРУКТУРНО не видит cli-подграф КОРНЕВОГО ЛОКА.** `npm-audit-exocortex` стоит в `packages/core`; `packages/cli` в его прод-граф не входит **никогда**. Живая high-advisory в том, из чего мы **собираем и тестируем** (корневой лок, тот самый, по которому каждый CI-раннер делает `npm ci`), спокойно сосуществует с зелёным гейтом — это не флак и не отставание фида, а **позиционирование**. ✅ Floor при аудите security-гейтов: спросить не «зелёный ли», а **«покрывает ли `working-directory` прод-граф публикуемых пакетов»**; если нет — зелёный гейт не является утверждением о том, что отгружено. Вынесено наблюдением, в #4036 не чинилось (правка `working-directory` меняет то, что гейтит **каждый** PR, и требует своей верификации).
  - ⛤ **КОРРЕКЦИЯ 2026-08-07 (пост-мерж): «пользователи устанавливают» — НЕ замерялось и для этого случая ОПРОВЕРГНУТО.** Первая редакция этого буллета (и тела PR #4036) описывала слепое пятно как экспозицию **потребителей npm**. Замер: `npm view @kitelev/exocortex-cli dependencies.glob` → **`^11.0.0`** — публикуемый манифест несёт **диапазон**, а лок-файл npm в тарбол не кладёт ⇒ потребитель резолвит цепочку **заново при своей установке** и с 03.08 и так получал 5.0.9. Пин жил в **корневом** манифесте монорепо, который не публикуется. ⇒ экспозиция была **наша** (дерево + CI), downstream её не видел.
  - ⛤ **Оставшийся, и он сильнее прежнего: покрытие гейта и экспозиция пользователя — РАЗНЫЕ вопросы, и гейт не отвечает НИ НА ОДИН из них полностью.** Слепое пятно = утверждение о том, **из чего мы собираем**. Дойдёт ли конкретная непокрытая advisory до конечного пользователя, определяет **форма публикуемого манифеста** (диапазон ⇒ он резолвит сам и наш пин ему не указ; пин/шринкврап ⇒ уносит нашу резолюцию с собой). ⚠ Значит из «гейт зелёный» не следует ни «мы чисты», ни «пользователи чисты» — и это **две** проверки, а не одна.
- ⚠ **Оговорка «может быть gate-neutral» ПОДТВЕРДИЛАСЬ** (исход №1): бамп закрыл реальную prod-уязвимость и **не** перекрасил гейт (0 → 0 на CI-поверхности). Т.е. запрет «не писать в PR „фиксит красный гейт“, пока механизм не установлен» сработал по назначению — иначе в durable-артефакт уехала бы ложная подпись при верном действии ([[decision-surface-must-derive-from-mechanism]] §форма №6).
  - ⛔ **И тут же — рецидив той же формы №6 на СОСЕДНЕЙ оси claim'а.** Гейт-ось я охранял явно (запрет выше) и не переступил; но у того же утверждения есть вторая ось — **КТО выгодоприобретатель**, — и по ней я написал «пользователи устанавливают», не замерив. Охрана одной оси **не переносится** на другую: она сужает внимание к охраняемой формулировке и создаёт ощущение, что заявление в целом уже проверено. Поймал ОРКЕСТРАТОР независимым замером (`npm view … dependencies.glob`) — тот же актор и тот же механизм, что в §Empirical 2026-08-07 ниже, **в тот же день и в том же репо**. Разбор — [[decision-surface-must-derive-from-mechanism]] §Addendum 2026-08-07 (ось выгодоприобретателя).
- ✅ **Floor: в `overrides` предпочитать МИНИМАЛЬНОЕ ограничение точной версии** — `"^5.0.9"` вместо `"5.0.9"`, чтобы будущие патчи текли сами. ⛤ **Больше НЕ кандидат — ПРОВЕРЕНО 2026-08-07 (PR #4036, адверсарное ревью):** диапазонная форма override резолвится на 5.0.9 штатно. Заодно отбиты две конкурирующие гипотезы, и обе — пробой на реальном worktree от `origin/main`:

  | Гипотеза-соперник | Проба | Исход |
  |---|---|---|
  | «npm вообще не чинит вложенный узел» | override **снят целиком** | уехал на 5.0.9 сам ⇒ опровергнута |
  | «любой `overrides`-вход глушит фикс» | override → **диапазон** `^5.0.9` | уехал на 5.0.9 ⇒ опровергнута |

  ⇒ блокирует **именно точный потолок**, а не наличие override. Изоляция одной переменной. ⛤ Побочно: в этом репо пин **уже избыточен** — `minimatch@10.2.5` требует `^5.0.5`, и 5.0.9 достигается **без пина вовсе**; исходная причина пина (форсировать 5.x вверх, когда естественная резолюция была 5.0.7) отпала.
- ⛔ **МЕТОДОЛОГИЯ контрольного опыта в npm-workspace монорепо: только настоящий `git worktree`, НЕ копия манифестов.** Первая попытка ревьюера — скопировать `package.json` + `package-lock.json` в scratch-каталог — дала **ложное `found 0 vulnerabilities`**: без `packages/*` на диске npm вырезает весь workspace-граф, и «чисто» означает «нечего проверять». ⚠ Тождественно-зелёная проба ([[self-satisfying-metric-weak-verifier]]) — знать в лицо, потому что копирование манифестов выглядит аккуратнее и дешевле worktree.
- ⛤ **Симптом-tell на уровне корпуса, а не одного бампа: ТРИ касания одного override за две недели** (07-25 отложили → 07-27 запинили → 08-07 пин сам уязвим). Три касания — уже не череда совпадений, а признак, что точный пин на пакете под активным advisory-давлением требует **диапазона либо повторяющейся сверки**, а не очередного разового бампа.
- ⛤ **Зеркало `unpinned-ci-tool-version-drift`:** там незапиненный инструмент **дрейфует** и ломает CI на неизменном дереве; здесь запиненная зависимость **окаменевает** и держит уязвимость на неизменном дереве. Один класс «внешнее событие против замороженного локального состояния», две противоположные стороны пина.

**Empirical:** 2026-08-07. Найдено ребёнком `release-gate-audit` по ходу PR #4034 (вынес наблюдением, scope не расширял — верно).
