# Deploying a homoiconic `exo__Layout` (class-level feed) as vault-data — recipe + gotchas

## Принцип

Ан `exo__Layout` — гомоиконичный class-level UI-конфиг: vault-ассет (`exo__Layout` targetClass X + упорядоченные `exo__LayoutBlock`-инстансы), декларирующий body-layout для КАЖДОГО инстанса класса X. Развернуть его (напр. daily-efforts feed для `pn__DailyNote`, issue #3781) — **vault-DATA шаг (0 кода)**, но с load-bearing placement/visibility/suppression-граблями, которые ТИХО деградируют страницы целевого класса, если сделать неверно. Активация layout'а на ЖИВОМ vault без верифицированно-рендерящейся спеки = деградация → temp-vault/headless proof ОБЯЗАТЕЛЕН до push.

## Когда правило срабатывает

- Развёртывание/правка `exo__Layout` + его block-инстансов как vault-ассетов.
- Добавление гомоиконичного feed к классу (daily-note feed, area-layout, project-layout).

## Recipe (verified released-engine, origin/main 2026-07-12, `packages/core/src/domain/layout/`)

1. **Placement — найди, где layout-TBox РЕАЛЬНО живёт, НЕ предполагай exoas-exo** (`verify-before-assert`). В vault-my живые siblings `exo__Layout`(`08d00289`) + `exo__LayoutBlock`(`6bca6f8d`) лежат в **`exoas-shared-identities/shared-identities/`** (isDefinedBy `$shared-identities` `d1195402`), НЕ в exoas-exo (там layout-TBox вообще нет). Co-locate новый block-subclass (`exo__DailyEffortsByClassBlock` `22528ed6`) ВМЕСТЕ с родителем через совпадающий isDefinedBy → same-folder subClassOf. Шаблон concrete-block-subclass (starter-kit `exo/`): `exo__Instance_class:`8619c4fc`` (exo__Class metaclass) + `rdfs__subClassOf:[[6bca6f8d|exo__LayoutBlock]]`. **Class def = shared** (все vault); **layout-ИНСТАНС + блоки = personal** (`exoas-my/<pn-folder>`, только target-vault) чтобы ограничить blast-radius активации.
2. **Схема (parsers):** `Layout` = `exo__Layout_targetClass` (normalizeRef → матчит `normalize(note.instance_class)`; для label-класса pn__DailyNote → ``pn__DailyNote``) + `exo__Layout_blocks` (**упорядоченный** wikilink-массив, резолвится by uid ИЛИ label) + `exo__Layout_priority` + `exo__Layout_coexistsWithDefault`. `Block` = `exo__Instance_class:`<block-class>`` + `exo__DailyEffortsByClassBlock_partition` (actions|tasks|projects|closed) + `exo__LayoutBlock_title` + `exo__LayoutBlock_visible`.
3. **⛤ Visibility precedence:** per-note override (`pn__DailyNote_show<X>`) > **Layout-default** (`exo__LayoutBlock_visible`) > **built-in**. Для daily-efforts built-in **Projects = HIDDEN** (VL#3), Actions/Tasks/Closed = shown. → Чтобы показать Projects, ОБЯЗАН авторить `exo__LayoutBlock_visible: true` на projects-блоке (load-bearing; revert-verify: убрал → блок скипается, blockCount падает). Explicit `visible: true` на всех блоках = чистое «все показаны».
4. **Suppression — ⛔ «coexists=true» НЕ значит «no loss»:** активация ЛЮБОГО daily-efforts layout'а **подавляет весь legacy `DailyTasksRenderer` feed** (`dailyEffortsLayoutActive`). `coexistsWithDefault: true` сохраняет только **AreaTree + Relations**; `false` = full-replace (теряет и их). НО **сам legacy tasks-feed подавляется в ОБОИХ режимах** — а он рендерит **богатую TIME-TABLE** (колонки Name/Start/End/Status, тайминги задач, **пустые слоты**, контролы `Hide Empty Slots`/`Hide Time`/`Show Time Est`/`focus`). Плоские daily-efforts-блоки (Actions/Tasks/Projects/Closed) — **списки БЕЗ времени/слотов/статуса** → замена time-table плоскими списками = **регрессия для пользователя, который планирует день по таймингам** (см. Empirical 2026-07-12 rollback). ⛤ `coexists=true` — «additive» лишь относительно AreaTree/Relations, НЕ относительно tasks-time-table. Перед деплоем **сравни фичи**: что даёт legacy renderer (BEFORE-скриншот) vs что даёт новый feed (AFTER) — если новый НЕ superset → это регрессия, требует explicit user sign-off ИЛИ time-table-блока в layout.
5. **Gate:** settings-флаг **`enableExoLayoutRenderer` ОБЯЗАН быть ON** (`data.json`), иначе layout вообще не активируется (`layoutActive = layout !== null && settings.enableExoLayoutRenderer`).

## Verify (temp-vault / headless — `ui-smoke-transitive-proof` real-file proof)

- **Headless real-file resolution proof:** throwaway jest в origin/main worktree — распарсить АВТОРСКИЙ `.md`-frontmatter через `createLayoutFromFrontmatter`/`createLayoutBlockFromFrontmatter`, затем прогнать реальный `LayoutSelector.resolve` + `ExoLayoutRenderer.render` над синтетическими day-efforts → assert блоки рендерятся в авторском порядке, все показаны, partitions заполнены. **Revert-verify** visible-override (drop `visible:true` у Projects → RED). Сильнее, чем hand-built domain-объекты — гоняет движок над твоими vault-данными.
  - ⛤ **uuid v13 ESM-грабля:** импорт RUNTIME-символов из `@kitelev/exocortex-core` тянет core-barrel (index.ts) → `uuid` v13 (pure ESM); plugin jest `transform` обрабатывает только `.tsx?` → `SyntaxError: Unexpected token 'export'` (suite failed to run, 0 tests — НЕ настоящий RED). Fix в throwaway-worktree: `moduleNameMapper "^uuid$"` → минимальный CJS uuid-мок (exports v5/v4/validate/…). Shipped renderer-тесты обходят это **type-only** core-импортами + hand-built domain-объектами.
    - ⛤ **ЛУЧШЕЕ лекарство (2026-08-19): не правь тест-конфиг — восстанови ПАРИТЕТ С CI.** Симптом
      (`Must use import to load ES Module: …/node_modules/uuid/dist-node/index.js`, `Tests: 0 total`)
      возникает не от твоей правки, а от того, что worktree собран `cp -a node_modules`: хойстнутый
      `uuid` там 13.x (pure ESM), а **пакет-локальной** копии нет. Чистый `npm ci` в CI её создаёт —
      поэтому CI зелёный, а локально набор не собирается. Восстанавливается одной командой:
      ```bash
      T=$(mktemp -d) && (cd "$T" && npm pack uuid@11 >/dev/null && tar -xzf uuid-*.tgz) \
        && rm -rf packages/core/node_modules/uuid \
        && cp -R "$T/package" packages/core/node_modules/uuid && rm -rf "$T"
      ```
      ⛤ Строго лучше `moduleNameMapper`+мока: (а) ничего не коммитится и нечему протухнуть,
      (б) исполняется **настоящий** пакет, а не твоя реконструкция его API, (в) чинит ВСЕ наборы
      пакета разом, а не тот, где заметил. ⚠ Дискриминатор «это окружение, а не я»: прогнать
      **пристинную** версию файла (`git checkout -- <тест>`) — падает так же ⇒ окружение.
      Эмпирика: 0 запускавшихся наборов → 492 теста в 29 наборах после установки v11.1.1. `cp -a node_modules` из свежего origin/main-worktree; core резолвится в **src** через moduleNameMapper (build не нужен).
- **SHACL 0:** валидировать на **hard-link temp-vault** (`cp -al assetspaces` — мгновенно) + твои файлы → delta 0 (0 violations, ссылающихся на твои UID). Co-location audit чист. (rm cache перед validate, `shacl-validate-clear-cache`.)
- **Pixel-visual** = ~1-мин user-confirm (DailyEffortsBlockView-рендер = a38ac95b-verified path; дельта = новый partition) — ⛔ НЕ мутировать живой vault ради теста (`gui-mutation-test-on-temp-vault`).

## Deploy

Bottom-up **Write** (class def → блоки → layout, чтобы не было forward-ref wikilink-блока; `vault-asset-creation` hook-coverage) → **SHACL post-validate** live (rm cache) → **ExoSync push** → **verify remote через `gh api contents?ref=main`** (НЕ `pushed`-счётчик — живой Obsidian-plugin ExoSync может авто-пушнуть первым, показав `pushed 0`; `migration-pre-verify-use-case` push=additive, parity ДО push).

## Empirical

- **2026-07-12, #3781** daily-efforts feed для pn__DailyNote (child, PR #3898 отгрузил `closed`-partition код). 6 ассетов: class def `exo__DailyEffortsByClassBlock` (exoas-shared-identities) + `exo__Layout` + 4 блока (exoas-my/my-pns, coexists=true, все visible:true, порядок Actions→Tasks→Projects→Closed). Headless proof **4/4 + revert-verified**; SHACL delta 0; co-location clean; live pixel-visual показал 4 блока в порядке. Placement-находка (siblings в shared-identities, не exoas-exo) — verify-before-assert поймал ДО авторинга.

- ⛔ **РЕГРЕССИЯ + ROLLBACK (тот же #3781, через ~30 мин после «PASS»):** deploy **подавил legacy TIME-TABLE** — Андрей в проде: **«нет таблицы, в которой можно видеть время задач, пустые слоты — это очень критично!!!»**. Плоский daily-efforts feed заменил богатую tasks-time-table (Start/End/Status/empty-slots). **Deploy откачен под ключ:** 6 ассетов удалены local+remote (ExoSync `deleted 5` exoas-my + `deleted 1` shared-identities, remote 404), Obsidian reload → **legacy time-table восстановлена** (pixel-visual: колонки Name/Start/End/Status + `Hide Empty Slots` вернулись). Backup 6 ассетов в scratch (reversible).
  - **Двойной урок verify-before-assert:** (1) headless proof + live pixel-visual верифицировали, что НОВЫЙ feed рендерится — но **НИ ОДИН шаг не охарактеризовал, что даёт ПОДАВЛЯЕМЫЙ legacy renderer** (time-table). Регрессия = ПОТЕРЯ фичи, невидима проверке «новое рендерится». **Floor: перед деплоем layout'а, подавляющего sibling-renderer — сделай BEFORE-скриншот legacy-вида, AFTER-скриншот нового, СРАВНИ feature-completeness; новый обязан быть SUPERSET ИЛИ явный user sign-off на потерю.** (2) «coexists=true / additive» усыпило бдительность — оно additive лишь для AreaTree/Relations, а tasks-feed (time-table) подавляется всегда (см. §Suppression correction). Ни headless, ни orchestrator-pixel-visual этого не поймали — поймал пользователь в проде. Rollback был чистым (backup + local+remote delete + reload-verify) — но регрессии-в-прод можно было избежать BEFORE/AFTER-сравнением.
