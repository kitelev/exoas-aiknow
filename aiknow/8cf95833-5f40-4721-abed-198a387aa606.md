# Developer/* конфиг-файлы — симлинки в dotfiles: sed/Edit/grep ведут себя по-разному

## Принцип

Конфигурационные файлы под `/Users/kitelev/Developer/` (и его подпапками вроде `exocortex-development/`) — в значительной части **симлинки в `/Users/kitelev/dotfiles/`**:

- `/Users/kitelev/Developer/CLAUDE.md` → `~/dotfiles/Developer/CLAUDE.md`
- `/Users/kitelev/Developer/exocortex-development/CLAUDE.md` → `~/dotfiles/Developer/exocortex-development/CLAUDE.md`
- `~/.claude/{skills,agents}` → `~/dotfiles/.claude/{skills,agents}`

Инструменты реагируют на симлинк **тремя разными способами** — два из них тихие/запутывающие:

| Инструмент | Поведение на симлинке | Опасность |
|---|---|---|
| `sed -i ''` | **Явный fail**: «in-place editing only works for regular files» | Низкая (шумит) |
| `Edit`/`Write` tool | **Явный refuse**: «Refusing to write through symlink … pass the real target path» | Низкая (шумит) |
| `grep -r` / `grep -rln` | **Молча пропускает** симлинк-файлы (не следует symlink при рекурсии) | ⚠️ ВЫСОКАЯ — false-negative «вхождений нет», когда они есть |
| `cp -a <симлинк-каталог> <dst>` | **Молча создаёт СИМЛИНК** (`-a` = `-pPR`, а `-P` симлинку не следует) — «копии» не возникает | ⛔ КРИТИЧЕСКАЯ — последующие `rm`/`mv` «внутри копии» мутируют ЖИВОЙ каталог |
| harness скиллов (`dir:skill` scoped-вариант) | **Объявляет вариант ОТДЕЛЬНЫМ скиллом** и предписывает вызвать его, хотя `~/.claude/skills` — симлинк в dotfiles ⇒ файл ОДИН | ⚠ вызов варианта инжектит ТО ЖЕ тело второй раз (у крупного скилла — сотни КБ) без единого нового байта |

⛤ **Scoped-вариант скилла (`<dir>:<skill>`) при симлинкнутом `~/.claude/skills` ТОЖДЕСТВЕН unscoped — вызывать его НЕ надо.** Harness выводит варианты из путей и о симлинке не знает.

- ✅ **Дискриминатор:** `shasum ~/.claude/skills/<s>/SKILL.md ~/dotfiles/.claude/skills/<s>/SKILL.md` — совпало ⇒ файл один.
- ⚠ **Tell:** system-reminder предлагает вариант, а `readlink ~/.claude/skills` непуст.
- ⛔ Цена не косметическая: тело инжектится ЦЕЛИКОМ на вызов ⇒ второй инжект приближает `Prompt is too long`.

## Правила

1. **Перед правкой** конфиг-.md под `Developer/` — `ls -la <file>`: если симлинк → работать с **реальным путём в dotfiles** (он же нужен для commit+push).
2. **Рекурсивный grep по папке с конфигами** (`grep -r <pattern> <dir>/`) — НЕ доказательство отсутствия: симлинк-файлы молча пропущены. Для negative claims: прямой `grep <pattern> <file>` по каждому известному конфигу ИЛИ grep по `~/dotfiles/` (реальные файлы там).
3. **После правки в dotfiles** — изменения видны по обоим путям мгновенно; commit+push только в dotfiles repo.

4. ⛔ **Копируя каталог под `~/.claude/` для изолированной пробы — копируй СОДЕРЖИМОЕ реального каталога, не путь-симлинк:** `SRC="$(cd ~/.claude/<dir> && pwd -P)"` → `cp -a "$SRC/." "$DST/"`. ⛤ Единственный дешёвый детектор — **канарейка изоляции** сразу после копирования: `[ ! -L "$DST" ] && [ -d "$DST" ]` плюс «предмет мутации ЖИВ в источнике». ⚠ **Tell до запуска:** в пробе есть `cp -a ~/.claude/…` и следом `rm`/`mv` внутри назначения. ⛤ Класс — Г17 в `bash-loop-eval-pitfalls` (`ln -sf` сквозь цель-каталог); `cp -a` — третий носитель.
