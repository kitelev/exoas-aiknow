## Разборы

## §A1 Empirical reference (PRODUCTION-side mirror: a VALIDATOR calling a lower-level API than production uses checks a code path no real object ever takes)

Every reference above is about a TEST fixture diverging from the real contract. The same failure family has a **production-code** mirror worth naming, because it yields a *false verdict* rather than a false green. When you build a check that inspects a candidate object, it is natural to call the **inner** API directly — it takes exactly the inputs you already hold in memory. But production usually reaches that inner API through a **wrapper**, and the wrapper's pre/post work is part of the contract. Bypass it and your check exercises a shape the real system never ingests.

- **Floor:** before validating a candidate through an inner API, **enumerate what the production wrapper does around that API** — pre-validation, skip/filter gates, error swallowing, normalisation — and replicate each half. `grep` the wrapper's call to the inner API and read the code immediately before *and* after it. If the wrapper SKIPS an input class, decide explicitly whether your check skips or reports it; never let it fall through to a raw exception.
- ⛤ **Symptom-tell:** an input class production merely *drops quietly* surfaces from your checker as a **raw low-level exception** (`Literal value cannot be empty`, `Cannot read properties of null`) instead of a domain verdict. That asymmetry — production shrugs, your checker explodes — is the signature.
- **Semantic choice this forces:** if the wrapper would SKIP the object entirely, "skipped" is rarely a pass. An object the indexer skips contributes **zero** data and is invisible to every downstream consumer — usually *worse* than the constraint you were checking. Prefer reporting it as a failure, with a message that says why the silence is the danger.
- **Empirical (2026-07-31, `create --validate`, PR #4009 → CLI v16.204.0):** the pre-write SHACL gate called `NoteToRDFConverter.convertNoteFromFrontmatter` directly, while production ingestion (`convertVault`) wraps it in a two-phase commit (#2997) that runs `validateExocortexAsset` **before** converting and **discards the buffer on any throw**. An empty optional property (`--property ems__Effort_status=`) therefore crashed with a raw `Literal value cannot be empty` instead of returning a structured verdict — defeating the requirement's machine-readable-error clause for a fully reachable input. Caught by an adversarial `code-reviewer` pass (its only MEDIUM), **not** by the 6 passing tests. Fix: invariant pre-check (which also fails **fast**, before the vault-wide load) + try/catch backstop, reporting an unindexable candidate as a violation. Cost: 1 review round; caught pre-merge.

## §A2 ⛤ Addendum 2026-07-31 — фикстура может быть production-shape по ДАННЫМ и при этом не воспроизводить ВРЕМЕННОЙ РЕЖИМ реальной нагрузки (tight loop vs duty cycle)

Всё правило выше — про **форму данных и границу стаба**. Есть третья ось, по которой харнесс расходится с продом и которая не видна ни в одном ассерте: **тайминг**. Харнесс почти всегда бьёт **плотным циклом** (N итераций подряд, чтобы прогон уложился в минуты), а продовая нагрузка приходит **редкими вызовами с паузами** (минуты-часы между ними). Для дефектов, чей механизм зависит от того, что происходит **между** вызовами — сжатие/выгрузка страниц ОС, истечение TTL кэша, закрытие пула соединений, GC-давление, переподключение сокета — плотный цикл структурно **не может** воспроизвести баг: он никогда не входит в состояние, из которого баг растёт.

- **Симптом-tell:** серия проб последовательно опровергает гипотезу за гипотезой, и все они **одинаково устроены по времени**. Если каждая проба — «N итераций подряд», то ты не проверил N гипотез, ты N раз проверил один и тот же режим.
- **Floor:** прежде чем писать «механизм не воспроизводится», выпиши **временной профиль прода** (сколько вызовов за какое окно) и сравни со своим харнессом. Расхождение на порядки (60 вызовов за 90 с против 200 за 14 ч = ~4-минутные паузы) — это **непроверенное измерение**, а не фон.
- **Как проверять:** мерить не только «до/после серии», но и **до вызова / после вызова / после паузы** — тогда видно, что именно делает пауза (у памяти: падает ли RSS за паузу при растущем footprint = страницы ушли в compressed и вернулись).
- ⚠ **Duty-cycle может требовать со-фактора.** Механизм, зависящий от реакции ОС (сжатие памяти), проявится только под соответствующим давлением: на разгруженной машине compressor может вообще не работать, и та же проба даст ложно-отрицательный результат. Фиксировать со-фактор (свободная память, нагрузка) в описании прогона, иначе «не воспроизвелось» неинтерпретируемо.

## §A3 ⛤ Addendum 2026-08-03 — фикстура задаёт не только ФОРМУ значения, но и его ТИП: незакавыченная дата в YAML приходит как `Date`, и строковые литералы делают фичу мёртвой на 100% данных

Предыдущие аддендумы — про фикстуру, которая не воспроизводит *путь загрузки* или *временной режим*. Третья ось: фикстура воспроизводит форму значения (`"2026-08-01"`), но **не его тип**. Здесь ловушка резче, потому что тип не виден глазами — в тесте и в ассете написана одна и та же строка символов.

- **Механика:** незакавыченный `life__Episode_start: 2026-04-02` — это YAML-**timestamp**, парсер отдаёт `Date` (и **UTC-полночь** для zone-less значения). Закавыченный `"2026-04-02"` — строка. Реальные ассеты пишутся без кавычек, потому что так их создаёт CLI; тесты пишутся с кавычками, потому что так удобно печатать. ⇒ `typeof raw !== "string" → return null` проходит все тесты и отбрасывает **каждый** реальный ассет.
- ⛔ **Симптом отсутствует.** Не падение, не исключение, не предупреждение — фича просто никогда не срабатывает. CI зелёный, ревью формы кода ничего не видит, живой смок покажет дефект только если его вообще проводить.
- ⛤ **Почему в ОДНОМ vault сосуществуют ОБЕ формы — это не случайность, а дефект производителя.** Формулировка выше («реальные ассеты пишутся без кавычек, потому что так их создаёт CLI») верна лишь для `create`: **`set-property` квотирует scalar-значения всех свойств**, поэтому то же самое свойство, будучи ПОЗЖЕ отредактированным, приезжает строкой ([[vault-asset-creation]] §create-vs-set-property; дефект `34b0a52c`). ⇒ «прогнать парсер на реальном ассете» (floor ниже) обязано брать **оба** образца — созданный и правленый; одного мало, потому что тип зависит от того, какая команда трогала свойство последней. Пока производитель не унифицирован, потребитель принимает **оба** типа.
- ✅ **Floor:** прежде чем писать type-guard по значению frontmatter — **прогнать реальный парсер на реальном ассете**: `node -e "console.log(typeof require('js-yaml').load(<frontmatter>).<prop>)"`. Секунда работы против фичи, уехавшей мёртвой.
- ✅ **Конвенция репо сильнее интуиции:** грепни `instanceof Date` — если в проде уже девять мест ветвятся по нему, значит `Date` из frontmatter это норма, а не экзотика, и твой guard обязан её знать. Там же читается и правильное чтение дня (**UTC**-геттеры: zone-less timestamp = UTC-полночь; локальные назвали бы предыдущий день западнее UTC).
- ⛤ **Смежная асимметрия:** «сегодня» берётся **локальными** геттерами, а значение из frontmatter — **UTC**-геттерами. Это не рассогласование, а два разных смысла: «день, который пользователь проживает» против «день, который автор написал». Смешивать их в одну сторону — и есть off-by-one.

## §A4 ⛔ Addendum 2026-08-09 — ЧЕТВЁРТАЯ ось, и она НЕ про расхождение с продом: фикстура рассогласована САМА С СОБОЙ (две записи ОДНОЙ величины вычислены независимо)

Все три оси выше — про зазор **фикстура ↔ прод** (форма/тип значения · граница стаба · временной режим), и все три лечатся сверкой с продом. Четвёртая живёт **внутри** фикстуры: она пишет **две** записи, которые предмет сравнивает **на равенство**, и вычисляет их **двумя независимыми замерами** одной и той же логической величины.

⛤ **Тогда тест недетерминирован ПО СРЕДЕ, а не по коду:** пока оба замера попадают в один тик источника — зелено; как только между ними переползает граница (секунды, минуты, счётчика) — предмет видит **разные** значения и уходит в ветку «состояние сменилось».

- ⛔ **Класс шире времени.** Тот же дефект даёт любая пара, обязанная совпасть: два независимых `uuidgen` на «один и тот же» объект, два чтения счётчика, два `git rev-parse HEAD` вокруг мутации, две выборки «сейчас» из БД. Признак — **предмет сравнивает записи на равенство**, а фикстура порождает их порознь.
- ⚠ **Симптом читается как «среда шумит», и потому уводит в ложную гипотезу.** Наблюдаемое — «краснеет 1 из N на неизменном коде», и естественное объяснение всегда внешнее (панель не отрендерилась, сеть моргнула, планировщик). ⛔ Прежде чем чинить ожидание/`sleep` — прочитай, **использует ли предмет** тот сигнал, на который ты грешишь: если ветка, дающая ожидаемый исход, выносится **до** его чтения, гипотеза опровергнута, не начав.
- ✅ **Floor: ОДИН источник на логическую величину.** Вторая запись **читает** первую (`reset` берётся из уже написанного снимка), а не вычисляет заново. Согласованность становится свойством **конструкции** — её нельзя разрушить ни порядком вызовов, ни числом полей, ни нагрузкой машины. Порядок при этом становится несущим ⇒ закрепи его **fail-loud guard'ом**, а не комментарием.
- ⛤ **Мутант для такой оси обязан быть ДЕТЕРМИНИРОВАННЫМ.** Возврат прежней формы (два независимых замера) воспроизводит дефект **вероятностно** — то есть сам становится флаки-мутантом, запрещённым [[integration-test-revert-verify]] §Addendum 2026-08-09 (ВЫБИРАЯ мутанта: флаки хуже отсутствующего). Брать **гарантированный** худший случай (`+1` к одной из записей): он моделирует ровно то состояние, которое прежний код давал случайно.
- ⛤ **Поверхность почти всегда ШИРЕ одной оси, и это стоит померить мутантом.** Рассогласование ломает **все** сценарии, где ожидается «состояние изменилось», и маскируется ровно там, где ожидаемый исход совпадает с исходом сброса. ⚠ Отсюда практический вывод: сценарии, оставшиеся зелёными под мутантом, были зелены **по неверной причине** — их REVERT-смысл («потолок отключён») подменялся на «величина не посчитана».
