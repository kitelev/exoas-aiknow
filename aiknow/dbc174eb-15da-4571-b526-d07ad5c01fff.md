# Reverse image search локального файла: буфер обмена + Cmd+V, а НЕ file_upload/upload_image

## Принцип

Чтобы прогнать **локальный файл-картинку** через обратный поиск (Яндекс.Картинки / Google Lens / TinEye) в браузерной автоматизации (`claude-in-chrome`), **надёжный способ — положить изображение в системный буфер macOS и вставить Cmd+V** в диалог визуального поиска. Прямые tool-пути не работают:

- ⛔ `mcp__claude-in-chrome__file_upload` **больше не принимает host-пути** → `file_upload no longer accepts host filesystem paths` (обновление тула; параметр `paths` устарел).
- ⛔ `mcp__claude-in-chrome__upload_image` требует **imageId из истории сообщений** (скриншот `ss_…` или user-upload), а НЕ имя файла/путь → на угаданный id `Unable to access message history to retrieve image`.
- ⛔ `navigate` на `file://` → `Can't interact with browser-internal or unparseable URLs`.
- ⚠ Кнопка «Вставить из буфера» на странице (JS `navigator.clipboard.read()`) в автоматическом браузере часто НЕ срабатывает (нет доступа к буферу / нет user-activation). **Работает именно нативная вставка Cmd+V** (`computer key cmd+v` в фокус диалога) — страница получает paste-событие с файлом.

## Рецепт (проверено на Яндекс/Google Lens/TinEye)

```bash
# 1. положить PNG в буфер macOS (для JPG — «class JPEG»)
osascript -e 'set the clipboard to (read (POSIX file "/abs/path/img.png") as «class PNGf»)'
```
```
# 2. открыть диалог визуального поиска:
#    Яндекс: yandex.com/images → иконка камеры; Google: images.google.com → иконка Lens; TinEye: tineye.com
# 3. computer key "cmd+v" в фокус диалога → страница ингестит картинку и уходит на страницу результатов
# 4. screenshot результатов
```

- Смена искомого фото: `osascript … set clipboard` на новый файл → снова открыть диалог (иконка камеры) → Cmd+V.
- Размер файла не важен (osascript кладёт в буфер целиком); base64-инъекция в JS не нужна и тяжела.

## Интерпретация результатов (OSINT / проверка на скам)

- **Движки:** Яндекс — сильнейший по лицам/людям и СНГ-контенту (нашёл первоисточник модели там, где Google/TinEye — нет). Google Lens — вкладка **«Точные совпадения»** для exact-match. TinEye — строгие дубликаты («0 matches» = не в его индексе).
- **«Похожие» ≠ «Сайты».** «Сайты» = страницы, содержащие ЭТО (near-)изображение; «Похожие» = визуально похожие (напр. тот же товар на другой модели). Не путать «такой же костюм» с «тот же кадр» — сравнивать превью источника с оригиналом (zoom).
- **Каталожный/товарный перекос:** если фото — модель в конкретной одежде, движки часто ключуются на **одежду** (выдача = маркетплейсы, «женский костюм…»), а не на человека. Это уже сигнал (постановочное/промо-фото).
- **Чистый кадр важнее.** Скриншот-в-скриншоте (со строкой статуса/интерфейсом) мешает exact-match. Обрезать до самого фото (`sips -c` центр, либо PIL `crop` со смещением), убрать UI, при нужде поднять лицо в кадр. Клип-версию тоже класть в буфер.
- **Отсутствие exact-match во ВСЕХ 3 движках (и по полному, и по обрезанному кадру) ≠ «уникально».** Может быть источник вне индекса (Instagram/Telegram продавца, закрытая витрина) ИЛИ пере-сжатый/обрезанный кадр. Формулировать «точный источник не найден», НЕ «фото уникальное» (`verify-before-assert`).
- **⛤ Зеркально (двусмысленность работает в ОБЕ стороны): НАЛИЧИЕ фото на сайте ≠ «украдено / личность фейковая».** Человек мог БЫТЬ моделью/субъектом той съёмки; его реальное фото могли репостнуть. Прежде чем заявлять кражу личности — **открой страницу-источник и прочитай АТРИБУЦИЮ**: названа ли ДРУГАЯ модель по имени (сильный сигнал импперсонации), это стоковое / иллюстрация к статье / листикл (нейтрально), или субъект вообще не назван. «Фото встречается на сайте X» — факт; «фото украдено / персона фабрикована» — ВЫВОД, требующий чтения контекста (`verify-before-assert`). Импперсонация подтверждается **несовпадением атрибуции** (на сайте фото подписано другим именем/профессией, чем в профиле), а не самим фактом «фото нашлось».
- **«Та же модель / та же съёмка» ≠ «тот же кадр».** Обратный поиск часто выдаёт кадры-близнецы одной сессии (та же одежда/локация/реквизит, другая поза/фон). Прежде чем заявлять «это ровно то фото» — **сверь ТОЧНЫЙ кадр** (поза, положение реквизита, фон), в идеале открыв оригинал рядом (Preview/QuickLook) и найдя точный кадр в галерее источника. «Тот же человек / та же съёмка» доказывается легко; «тот же кадр» — только покадровой сверкой.
