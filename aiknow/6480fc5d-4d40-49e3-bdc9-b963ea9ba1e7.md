# Retrieval: правила по концептам промпта (`$concepts`, `$rules`)

Несущий запрос графового пути retrieval правил (RFC 9d5ffe26 v3, §Архитектура п. 1; фаза 1 программы 204e2439, расширен фазой 4). Зовёт хук `rules-symptom-retrieval` при `RSR_SOURCE=graph` (фаза 4) и — как временный второй слой — модель через Gate 0 (`/context-loader`, `/knowledge-search`): `exocortex-cli run-query <uid> --vault <узкий mount exoas-aiknow> --format json --param concepts=<UID концептов через запятую> --param rules=<UID тел реестра rules-graph-pilot.json через запятую>`.

Параметры подставляются `NamedQueryRunner` экранированными строковыми литералами: `$concepts` — список UID концептов промпта, `$rules` — список UID тел правил реестра (89 UID ≈ 3 292 символа, проходит через argv). Оба фильтра — `CONTAINS` по литералу-списку.

Выход — строки `(rule, ru, label, concept, fanout, M)`: `rule` — IRI тела правила, `ru` — его `exo__Asset_uid` (ключ для реестра uid → имя роутера), `label` — метка, `concept` — UID концепта (или локальное имя при symbolic-форме объекта), `fanout` — число правил РЕЕСТРА, связанных с этим концептом (подзапрос с тем же фильтром `$rules` внутри — иначе fan-out считался бы по всем субъектам ассетспейса, ревью v3 находка №1: 3 против 1), `M` — число правил реестра с ≥ 1 связью (скалярный подзапрос под тем же `$rules`). Логарифм `gain = log2(M / fanout)` считает вызывающий код — `LOG()` движок не парсит.

**Порог специфичности — ДАННЫЕ этого запроса, не константа хука (AC13 RFC 9d5ffe26).** Строка `FILTER(?fanout * 4 <= ?M)` пропускает только концепты с `gain = log2(M / fanout) ≥ 2` бита: минимальный gain 2 бита ⇒ множитель 2² = 4 (концепт связан не более чем с четвертью правил реестра). Смена порога — правка этой строки (множитель = 2^minGain: 1 бит → 2, 1.5 → 2.83, 3 → 8), хук её не дублирует. Калибровка 2026-09-14 на tune (`rules-graph-threshold-sweep.py`): при fan-out max 8 и M = 89 минимальный gain по корпусу 3.48 бита — порог 2 бита не отсекает ни одного концепта; первый нарушитель AC13 (правило, у которого ВСЕ концепты ниже порога) появляется лишь при minGain > 5.48 бита (log2(89/2)).

Форма объекта ребра `aiKnow__Memory_aboutConcept` снимается двумя ветвями `BIND`: file-IRI с путём (vault-exodev) и беспутевая (узкий mount, концепты не смонтированы) — хвост `<uid>.md`; symbolic-форма `…/ontology/concept#<Local>` (если концепт получит parseable-метку) — хвост после `#`. Пустой `$rules` даёт 0 строк: вызывающий обязан отказывать на пустом реестре (BROKEN), а не читать пустую выдачу как «правил нет» — при пустом литерале и `fanout`, и `M` считались бы по всем субъектам ассетспейса.

```sparql
PREFIX aiKnow: <https://exocortex.my/ontology/aiKnow#>
PREFIX exo: <https://exocortex.my/ontology/exo#>
SELECT ?rule ?ru ?label ?concept ?fanout ?M WHERE {
  ?rule aiKnow:Memory_aboutConcept ?c .
  ?rule exo:Asset_uid ?ru .
  ?rule exo:Asset_label ?label .
  BIND(IF(CONTAINS(STR(?c), "#"),
          REPLACE(STR(?c), "^.*#", ""),
          REPLACE(STR(?c), "^.*/([^/]+)\\.md$", "$1")) AS ?concept)
  FILTER(CONTAINS($concepts, ?concept))
  FILTER(CONTAINS($rules, STR(?ru)))
  {
    SELECT ?c (COUNT(DISTINCT ?r) AS ?fanout) WHERE {
      ?r aiKnow:Memory_aboutConcept ?c .
      ?r exo:Asset_uid ?rr .
      FILTER(CONTAINS($rules, STR(?rr)))
    } GROUP BY ?c
  }
  {
    SELECT (COUNT(DISTINCT ?rm) AS ?M) WHERE {
      ?rm aiKnow:Memory_aboutConcept ?cm .
      ?rm exo:Asset_uid ?rmu .
      FILTER(CONTAINS($rules, STR(?rmu)))
    }
  }
  FILTER(?fanout * 4 <= ?M)
}
ORDER BY ?rule
```
