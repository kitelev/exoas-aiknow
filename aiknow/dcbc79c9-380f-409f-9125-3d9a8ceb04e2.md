# PR stuck behind base — proactive `update-branch` unblock

## Симптом

PR имеет:
- `state: OPEN`
- `mergeable: MERGEABLE`
- `mergeable_state: behind` (или `mergeStateStatus: UNKNOWN`/`BLOCKED`)
- `behind_by ≥ 1` (часто accumulates до 5-10+)
- `autoMergeRequest: enabled` ← key signal — пользователь уже хотел merge, GitHub просто не выполняет

GitHub auto-merge **НЕ** auto-syncs branch с base в squash mode. Если "Require branches to be up to date" включён в branch protection — PR висит пока кто-то вручную не sync'нет.

## Когда правило срабатывает

Orchestrator session обнаруживает PR в этом состоянии:
- При проверке prerequisite перед спавном задачи которая зависит от merged PR
- При мониторинге CI/release pipeline
- При очистке stale PRs

## Действие

Mechanical low-risk auto-execute (per Auto-execute Open Follow-ups правило):

```bash
gh api repos/<owner>/<repo>/pulls/<PR-NUMBER>/update-branch -X PUT
```

Эффект:
- Создаёт merge commit от base → PR branch
- Триггерит CI re-run на новом HEAD (~4-5 мин)
- После CI зелёного auto-merge срабатывает → squash merge → Auto Release

## Не использовать когда

- `mergeable: false` — есть реальные conflicts, requires manual resolution
- `autoMergeRequest: null` — пользователь явно не хотел auto-merge
- CI имеет failed required checks — fix-forward needed first
- PR draft, или review pending (BLOCKED for review reasons)

## Validation pattern

```bash
gh api repos/<owner>/<repo>/pulls/<n> | python3 -c "
import json, sys
d = json.load(sys.stdin)
ok = (
  d['state'] == 'open'
  and d['mergeable']
  and d['mergeable_state'] == 'behind'
  and (d.get('auto_merge') or {}).get('enabled_at')
)
print('eligible' if ok else 'skip')
"
```

## Anti-pattern

⛔ Polling `gh pr view ... mergeStateStatus` каждые 60s in hope it'll resolve — won't, it's deterministically blocked until branch syncs.

⛔ Force-merge via admin override — кросс-cutting concern, breaks branch protection assumptions.
