## Разборы

## §A1 ⛔ Addendum 2026-06-16 — `git config --global` (и др. writes СКВОЗЬ симлинк) → секрет утекает в tracked dotfiles

Тот же симлинк (`~/.gitconfig` → `dotfiles/home/.gitconfig`) опасен **и на запись**: любая команда, пишущая в `~/.gitconfig` — прежде всего **`git config --global …`** — пишет **сквозь симлинк в tracked-файл dotfiles**. Если значение секретное (GitHub PAT в `url."https://x-access-token:<PAT>@github.com/".insteadOf`), оно попадает в рабочее дерево dotfiles → один `git add`+`commit`+`push` от утечки в запушенный репо.

### Правило (host-based тесты/автоматизация, которым нужны транзитные git-creds)

- ⛔ **НЕ `git config --global`** для секретных/транзитных значений на ХОСТЕ — пишет в симлинкованный tracked `~/.gitconfig`.
- ✅ **`GIT_CONFIG_GLOBAL=/tmp/test-gitconfig-$$`** перед `git config --global …` → `git config` пишет в non-tracked temp-файл; затем `rm -f "$GIT_CONFIG_GLOBAL"` на teardown. Секрет никогда не в tracked-файле.
- ✅ Для постоянной HTTPS-аутентификации — `credential.helper osxkeychain` (PAT в Keychain, не в файле) ИЛИ non-tracked `[include] path = ~/.gitconfig.local` (gitignored).
- ⛤ Sanity перед `git add` в dotfiles: `git -C ~/dotfiles show HEAD:home/.gitconfig | grep -c 'x-access-token'` и `grep -cE '(gh[a-zA-Z]_|github_pat_)' home/.gitconfig` — оба 0 going-forward.
- ⛤ Контекст-различие: rule `obsidian-plugin-e2e-docker-emulation.md` рекомендует `git config --global url."…x-access-token:${PAT}…"` — это **Docker-container-scoped** (там `~/.gitconfig` = контейнерный, не host-симлинк). На ХОСТЕ (computer-control journey) тот же паттерн = утечка. Граница: Docker → ок; host → `GIT_CONFIG_GLOBAL`.

## §A3 ⛔ Addendum 2026-07-12 — харнесс атомарными записями КЛОББЕРИТ симлинк `~/.claude/<file>` в реальный файл → тихий дрейф от tracked-копии dotfiles

Тело правила — про поведение инструментов НА симлинке (sed/Edit refuse, grep -r skip, git config write-through). Ещё один failure-mode того же семейства: **симлинк `~/.claude/<file>` → dotfiles может быть тихо ЗАМЕНЁН реальным файлом**, и тогда live-версия и tracked-копия расходятся молча.

- **Механизм (гипотеза; факт клоббера verified):** те `~/.claude`-конфиги, в которые пишет САМ харнесс — `CLAUDE.md` (`/init`, `#`-memory, ручная правка) и `settings.json` (`/config`, гранты прав, `/update-config`) — при **атомарной записи (temp-file + rename)** теряют симлинк: rename кладёт на его место реальный файл. Редко-пишемые харнессом (`mcp.json`, `agents`, `hooks`, `rules`, `skills`) — симлинк уцелевает. Точный rename in-flight не пойман (потому гипотеза), но паттерн однозначен: **склоббрены ровно 2 харнесс-пишемых файла из ~8**, оба.
- **Следствие:** после клоббера правки live-файла НЕ доходят до git — `auto-backup.sh` (hourly `git add -A` внутри dotfiles) не видит файл вне своего дерева → **тихий дрейф**. Наблюдалось: блок «codegraph Freshness gate» (2026-07-09) жил только в live `~/.claude/CLAUDE.md`, в tracked-копии его не было ~3 дня.
- **Проверка перед доверием tracked-копии:** `readlink ~/.claude/CLAUDE.md` (пусто/ошибка = реальный файл = симлинк склоббрен) + `diff ~/.claude/<f> ~/dotfiles/.claude/<f>`. ⛔ Не считать, что правка `~/.claude/CLAUDE.md` автоматически в git — при склоббренном симлинке нужно вручную синкнуть в dotfiles-копию + commit ([[commit-and-push]]). Родственно two-file-правке из session (правил ОБЕ копии, verified `diff` = identical).
- **Митигация деплойнута (A+B, 2026-07-12):** (A) восстановил симлинк `~/.claude/CLAUDE.md` → dotfiles (`ln -sfn`; контент был byte-identical, потерь 0); (B) **drift-guard в `~/dotfiles/scripts/auto-backup.sh`** (commit `a8f2ffd`): перед `git add -A` для `CLAUDE.md`+`settings.json`, если live = реальный файл (`[ ! -L ]`) И `! cmp -s` tracked → `cp live→repo`. No-op при живом симлинке (не cp-onto-self). Переживает повторный клоббер → дрейф ловится ≤1 час. Guard сразу вскрыл дрейф `settings.json` (real file + differs).
- **Empirical:** 2026-07-12, config-maintenance сессия (свод cross-links skill-routing + аудит CLAUDE.md-синхрона). Cost: ~3 дня необнаруженного дрейфа CLAUDE.md (codegraph-блок) + ручная синхронизация. Урон 0 (сведены byte-identical). Floor: харнесс-пишемый symlinked конфиг → перед доверием tracked-копии `readlink`+`diff`; drift-guard в auto-backup — механическая страховка от рецидива.

## §A4 ⛔ Addendum 2026-08-06 — ДВА ПРОТИВОПОЛОЖНЫХ исхода записи в симлинк: атомарная ЗАМЕНЯЕТ его, простая пишет СКВОЗЬ. Второе тише и разрушительнее

Addendum 2026-07-12 (выше) описывает **атомарную** запись (temp-файл + `rename`): симлинк **исчезает**, на его месте появляется реальный файл, а цель в dotfiles **цела**. Зеркальный случай — **простая** запись (`cat >`, `>`, `tee`): симлинк **цел**, а перезаписана **цель**. Различать обязательно — диагностика и цена у них разные:

| форма записи | что с симлинком | что с целью в dotfiles | как обнаруживается |
|---|---|---|---|
| атомарная (`Write`-тул, `mv`, `sed -i`) | заменён реальным файлом | **цела** | `readlink` пуст; `diff` live↔dotfiles расходится со временем |
| **простая (`cat >`, `>`, `tee`)** | **цел** | **перезаписана** | `git status` в dotfiles ⇒ **M** у файла, который ты не открывал |

⛔ **Второй случай опаснее по трём причинам:** (а) `readlink` показывает симлинк на месте ⇒ привычная проверка «не склоббрено ли» возвращает «всё в порядке»; (б) урон уходит **сразу в dotfiles**, то есть в единственную копию, а не в дрейф; (в) если цель — исполняемая инфраструктура (канал уведомлений, хук, обёртка), она **немедленно перестаёт работать**, и следующая ошибка приходит из совсем другого места.

- ⛤ **Типовой источник — подмена библиотеки СТАБОМ в тест-харнессе.** Каталог стабов собирают симлинками на боевые файлы (`ln -sf`), а затем ОДИН из них переопределяют `cat >`-ом — и запись уходит сквозь только что созданный симлинк. Форма выглядит безобидно: «пишу же в свой временный каталог».
- ✅ **Floor: `rm -f "$DST"` НЕПОСРЕДСТВЕННО перед `cat > "$DST"`**, если `$DST` мог быть симлинком. Одна строка, снимает класс целиком.
- ⛤ **Гвард обязан покрывать поверхность мутации, а не пару файлов** — манифест по всему каталогу-источнику ([[self-satisfying-metric-weak-verifier]] §манифест содержимого). ⚠ И он **детектив**, а не превентив: краснеет постфактум и не чинит; превентив — только `rm -f` выше и `[ -f ]` в цикле `ln -sf` ([[bash-loop-eval-pitfalls]] Г17).
- ⚠ **Симптом-tell:** инструмент, которого ты не трогал, начал отвечать «не сделано»/«не доставлено» вскоре после того, как ты собирал стабы. Смотреть надо не на инструмент, а на `git status` dotfiles.
