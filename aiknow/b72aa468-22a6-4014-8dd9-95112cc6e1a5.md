## Симптом

Termius (или любой SSH-клиент) с телефона не подключается к макбуку. Раньше работал, ничего не меняли.

## ⛔ Ложный след, на который уходит первый час

Рефлекс — проверять **SSH**: включён ли Remote Login, слушает ли порт 22, не блокирует ли файрвол, нет ли ограничений в `sshd_config`. Замер 2026-08-26: **все эти проверки были зелёными**, и ни одна не приблизила к причине.

⚠ Отдельно обманывает **адрес на интерфейсе**: `ifconfig` показывает Tailscale-адрес `100.x.x.x`, и это читается как «Tailscale работает». Адрес остаётся на `utun` даже у разлогиненной ноды — он не доказывает членство в сети.

## ✅ Дискриминатор — ОДНА команда, первым делом

```
tailscale status
```

- `Logged out.` / `BackendState: NeedsLogin` ⇒ **нода не в тайлнете**, дальше SSH проверять бессмысленно
- `Running` + пиры в списке ⇒ тайлнет жив, тогда копать SSH

Расширенно (различает «разлогинили» и «ключ протух»):

```
tailscale status --json | python3 -c "import json,sys; d=json.load(sys.stdin); s=d.get('Self',{}); print(d.get('BackendState'), s.get('KeyExpiry'))"
```

⛤ **Подпись истёкшего ключа**: `LoggedOut: false` в prefs (пользователь НЕ выходил) при `BackendState: NeedsLogin`. Расхождение этих двух полей и означает key expiry, а не ручной разлогин.

## Механизм

У ноды Tailscale ключ имеет срок жизни — по умолчанию **180 дней**. По истечении нода выпадает из сети **молча**: приложение запущено, демон работает, адрес на месте, ошибок нигде нет. Никакого уведомления на маке не появляется.

Замер 2026-08-26 — арифметика сошлась по двум независимым осям:

| ось | факт |
|---|---|
| относительно последнего входа | последний SSH-логин `23 Aug 21:46-21:53` (Алматы), `KeyExpiry` = `23 Aug 22:55` — ключ протух **через час** после того, как сессия закончилась |
| относительно даты настройки | файлы в `/Library/Tailscale` датированы `Feb 24`; **24 февраля + 180 дней = 23 августа** |

## Лечение

```
tailscale up --accept-routes
```

⛔ **Флаг обязателен, и его нельзя угадывать.** `tailscale up` отказывается менять настройки, не упомянув все non-default флаги, и **сам печатает точную форму** для этой ноды. Голый `tailscale up` откажет; `--reset` пройдёт, но **сотрёт** текущие настройки. Брать форму дословно из подсказки CLI.

Команда печатает одноразовый auth-URL, ждёт подтверждения в браузере (вход через Apple ID), затем `Success.`

## ⛔ Вердикт выносить ТРАФИКОМ, а не полями

После логина `InEngine` и `InMagicSock` у Self **остались `False`** — ожидание, что они станут `True`, оказалось неверным (это свойство полей Self, а не дефект). Проверять надо эффект:

```
tailscale ping <имя-пира>          # → pong ... via <ip> ⇒ трафик идёт
ssh -o BatchMode=yes <user>@<tailscale-ip> true
```

⚠ Ответ `Permission denied (publickey,...)` на пробу с `BatchMode` — это **успех**, а не отказ: соединение принято и дошло до аутентификации, просто ключ не предъявлялся.

## ⚠ Диагностическая слепота этой машины

`log show --predicate 'process == "sshd"'` из песочницы Bash-tool возвращает **пустоту** — проверено канарейкой (`log show --last 5m` дал 1 строку вместо тысяч). ⇒ «попыток подключения в логе не видно» здесь **не является фактом**, это артефакт песочницы.

Работающая замена — наблюдать за сокетом:

```
netstat -an | grep -E '\.22 .*ESTABLISHED' | grep -v 127.0.0.1
```

Она ловит соединение **до** аутентификации, поэтому различает «трафик не доходит» (проблема маршрута/Tailscale) и «доходит, но отвергается» (проблема ключа/пользователя) — то самое различение, ради которого обычно и лезут в лог.

## Профилактика

Веб-консоль Tailscale → **Machines** → нода → **Disable key expiry**. Иначе повтор ровно через 180 дней, снова без предупреждения.
